# Platform Authoring Library Guide

These modules transform schemas, values and package drafts without React, DOM, network, toast or query-cache dependencies. Server validation, source safety, closed schemas and graph compilation stay authoritative; the wire rules are in [the decoupling contract](../../../../docs/工作流解耦方案.md) and the [schema subset](../../../../docs/writing-extensions.md#固定协议与-schema-子集).

- `default`/`examples` need the per-node `x-signaldeck-schema: signaldeck.schema/2` marker. Codecs preserve marker and annotation presence and never add annotations to existing definitions; `schema/constraints.ts` keeps and checks the supported bounds.
- `schema/codec.ts` maps the object, array, primitive, `enum` and `const` parts of the subset to schema IR and `values/` maps values to value-entry IR. Round trips preserve optional-field omission, null values and array path rebasing, and recursive controls must handle every legal shape, including null roots. The codec rejects `type: "null"` nodes, which the server accepts, and parses `$ref` and discriminated `anyOf` unions, which the server rejects.
- `parameter-values.ts` keeps scalar, array, object and null parameter roots without wrappers; `schema/launch-input-state.ts` builds object-form drafts and browser shape checks (the backend validates every root); `schema/schema-template.ts` supplies template values. Keep omitted, null, empty and defaulted values distinct.
- `common/field-path.ts` owns diagnostic path tokens shared by generated forms and codecs; user-facing errors map to field labels and editor objects, never raw paths. Schema title and description are display metadata, never runtime fields.
- `common/resource-ref.ts` parses resource identities `key` or `key@version`; they are not workflow wiring paths, and selectors show declared names or generic labels.
- `package-source.ts` reads v2 package YAML and applies structural edits through the `yaml` document API; `package-authoring.ts` maps backend diagnostics to the affected authoring section. Never parse or edit YAML with regex or string splitting, and keep these transformations and deterministic diagnostic paths here rather than in pages.
- Fields, mappings, conditions, result sections and budgets are edited through controls on that single source, preserving untouched fields, optional omission and the import/export format; a generic dictionary or source textarea never replaces a supported authoring capability.

Tests: the colocated `*.test.ts` files under `schema/` and `common/` and beside `parameter-values.ts` and `mapping-sources.ts`. `values/` is exercised by `schema/launch-input-state.test.ts` and `src/components/platform-authoring/generated-form/schema-form.test.tsx`, `package-source.ts` by `src/pages/platform/package-expert.test.tsx` and `platform.test.tsx`; generated-form behavior is tested under `src/components/platform-authoring/`.

# Frontend E2E Guide

Playwright runs Chromium against an owned PostgreSQL database, local fake OpenAI HTTP provider, Temporal dev server, pinned artifact workers, command dispatcher and built frontend preview.

## Harness

- `../playwright.config.ts` starts owned processes without server reuse. Use `pnpm exec playwright test`; specs are independent and can run in parallel.
- `../scripts/start-playwright-backend.mjs` builds the shared plugin UI before starting plugin processes, so their release digests include the packaged browser assets. It derives PostgreSQL access from `DATABASE_URL` or the backend local default. It creates a unique `signaldeck_e2e_*` database and drops only that database on shutdown. The account requires create/drop permission; never use an application database as disposable test storage.
- Set `TEMPORAL_CLI` to Temporal CLI 1.8.3 with Server 1.31.2. The harness verifies those versions and owns a dev server on port 17233 (`SIGNALDECK_E2E_TEMPORAL_PORT` override). It does not attach to an existing Temporal server.
- Every invocation creates an owned temporary directory for Temporal data, CAS artifacts, immutable core bundles and Python environments. Shutdown waits for owned process groups, unlocks only directories under that owned path without following symlinks, then removes it. Do not delete any shared application volumes or core bundles.
- Default ports are API 8001, fake provider 18081, Notes 18082, Finance 18083, Oracle 18084 and frontend 4173. `SIGNALDECK_E2E_BACKEND_PORT` and `SIGNALDECK_E2E_FRONTEND_PORT` override API/frontend ports; fixture API requests follow the configured backend port. Independent plugins use separately owned databases; Finance injects a deterministic quote provider and Oracle injects a controlled sentiment HTTP client. Deployment connection presets are written only under the owned temporary directory. The provider port/base URL are overridable. The pinned worker uses Python 3.13.13; the locked local API interpreter is resolved through uv.
- `../scripts/start-playwright-frontend.mjs` builds with the E2E API base URL and starts Vite preview. `SIGNALDECK_E2E_BUILD_DIR` selects the shared build/preview output directory (default `dist`); concurrent instances need separate directories as well as ports. Backend CORS allows only the configured frontend port on `127.0.0.1` and `localhost`. Browser validation targets the production build. Logfire credentials/configuration and OTLP exporter endpoints are isolated so the local harness does not send telemetry to external services.

## Coverage

- `platform-fixtures.ts` uses v2 Package definitions and explicit global resource bindings. Disable YAML aliases when serializing reused schema objects; backend source safety remains authoritative.
- `workflow-packages.spec.ts` owns structured authoring against the shared YAML definition, merged edge reasons, readable cycle diagnostics, launch inputs, browser closure during execution, execution history, frozen settings and rerun identity. Source identity and persistence invariants may be asserted through fixture APIs; visible controls must not require source editing.
- `parameters.spec.ts` owns discovery and recursive editing of legal array-root input without expert mode; manual and scheduled launches must preserve values, including empty arrays, optional omission and immutable Run inspection. Do not restore a JSON textarea to satisfy obsolete locators.
- `decoupling.spec.ts` imports an unrelated Workflow through the public batch API, verifies schema/2 defaults and static hints, explicit values, mode-switch drafts, common presets, frozen declared results and historical reuse. It repeats with renamed fields and literal `includeRisk`/`reportId`/`collection` data, executes a schedule with explicit parameters and provenance, and races missing-only imports while isolating malformed sources.
- `faults.spec.ts` owns a separate held MCP process and verifies actual unknown write effects after cancellation, guarded replay and historical reads after plugin shutdown. A separate successful run without presentation declarations retains full generic output and confirmed operation/plugin ownership after plugin shutdown and the optional Temporal shutdown. Run `pnpm exec playwright test --config playwright.fault.config.ts` as a separate invocation to also stop only its harness-owned Temporal process and verify persisted history with both dependencies offline. The isolated configuration submits a nonce-bound file request to the harness; it does not signal discovered processes or expose product control routes.
- `runs.spec.ts` coordinates a held local HTTP request, then verifies running cancellation reaches actual stopped state without fabricating model output.
- `resources.spec.ts` verifies write-only credentials through save, read and reload.
- `scheduled-tasks.spec.ts` verifies explicit timezone/overlap/missed-fire window, synchronization status, trigger acceptance, independent Run provenance, failure history and retained runs after schedule deletion. It pins browser timezone to UTC.
- `tasks.spec.ts` exercises the four ordinary task forms with actual MCP plugin processes, durable execution, controlled model/market data, missing-model inline repair, uncertain-response retry, input reuse and immutable run/result evidence. Each scenario captures filled forms, ready-to-start settings and executed results at 375, 768, 1024 and 1440 pixels; trial clicks and viewport bounds verify key actions remain reachable. Evidence is saved under `output/playwright/task-experience/`. These are automated observations, not participant or external supplier acceptance.
- `history.spec.ts` creates more than one page of real runs and verifies server history filtering, stable pagination snapshots, preserved filters through result/evidence navigation and refresh. It selects a browser timezone whose calendar day differs from UTC to exercise local date boundaries and reload behavior.
- `expert.spec.ts` owns field/step/condition/source/service/budget authoring, shared definition drafts, readable diagnostic navigation, file import/export, graph zoom/pan and responsive controls. Mode switches must preserve unsaved connection credentials and installation drafts without storing credentials or issuing commands. Navigation preserves memory drafts; refresh/close warns before loss, explicit server task drafts restore after refresh, and pending reruns reuse only their stored command identity/token. Evidence is saved under `output/playwright/expert-experience/`.
- `shell.spec.ts` covers generic navigation without statically compiled plugin pages and responsive overflow at 375, 768, 1024 and 1440 pixels. It captures editor screenshots for visual inspection.

Use accessible role/label locators and explicit response/state waits. All modes, tooltips, dialogs, errors, empty/loading states, results and independent plugin pages must satisfy the [product UI contract](../../docs/产品说明.md#产品范围): do not render internal IDs, raw responses, stack traces, storage paths, schema, engine or binding details, or require JSON/YAML/cron entry. Preserve user-authored content and original business attachments in assertions.

For a browser experience review, define the user goal and success condition before each scenario, then find controls only from visible UI. Fixture APIs may prepare isolated data, and code/API inspection may diagnose failures, but must not complete the user's steps or supply hidden navigation during the walkthrough. Cover normal and recovery paths after each affected change and retain necessary before/after screenshots. Automated tests do not replace browser review and neither represents participant research.

Never call a real model provider or use arbitrary sleeps to make a failing assertion pass. Tests prove only the behaviors actually exercised; component tests and backend acceptance cover additional cancellation, failure and recovery boundaries. Coverage responsibilities above do not claim an unrun or newly changed test has passed.

# 执行引擎比较

本文保留 SD-TARGET-001 选型阶段的比较证据：2026-09-08 按原基线 `bca05dcd666e96561426224b89b0e06aed186a22` 的 T06/A16，对三个候选运行相同业务场景：A 完成后 B/C 并行、B 的后继 E 不等待 C、D 等待 B/C；多轮 Agent 的模型与工具结果确认后中断 Worker；两个 Run 使用不同动态工具 schema；取消、总 deadline、固定制品和重复启动。全部使用真实本地执行引擎与 Pydantic AI，外部模型/业务由可计数的本地 fake 控制。当前产品架构见 [`架构说明`](架构说明.md)，后续产品集成的完成记录见 [`STATUS.md`](../STATUS.md)。

## 决定

用户于 **2026-09-08 正式确定 Temporal** 作为产品唯一持久执行引擎，历史决定见 [STATUS.md](../STATUS.md)。实现固定 Python SDK **1.32.0**、本地 CLI **1.8.3**（内嵌 Server **1.31.2**）、Pydantic AI **2.40.0**。以下比较保留候选探针当时的覆盖限制，不用后续产品验收结果反向扩大探针的观测范围。

Temporal 在实际 Worker 硬中断后直接依靠历史恢复模型/工具调用及成功兄弟节点。候选取消探针分别覆盖直接活动节点和 AgentWorkflow→模型 Activity，没有覆盖完整父 Workflow→Agent Child→活动调用链。产品使用同一 Workflow/Child Workflow/Activity 生命周期承接声明式图和 Agent 调用，完整取消与恢复边界由产品集成回归覆盖。代价是确定性执行限制、独立引擎进程及旧 Worker 制品的保留和路由。

Prefect 是可行候选：官方 `PrefectDurability` 已证明调用结果恢复和新 Run 数据新鲜度。API 取消探针只覆盖等待 `asyncio.sleep` 的普通 Flow，没有覆盖 Agent 内模型或工具。普通 flow `retries=1` 没有恢复被 SIGKILL 的进程；增加引擎原生 Crashed→Scheduled Automation 后恢复成功。选择它需要额外维护崩溃重提交、恢复上限和失联检测策略。它的固定源码 loader 实验证明了旧源码选择，尚未证明完整容器/依赖闭包保留。没有将这些适配成本描述为 Prefect 不具备持久执行能力。

Hatchet 也已证明 durable child 检查点恢复、并发和独立任务取消。该探针自行维护 Pydantic AI 模型/工具到 durable child 的适配；取消父任务后，活动模型子任务在八秒观察窗口内没有停止，解除等待后仍完成。这项观测记录了该适配探针的父子取消限制。原生二十四小时 TTL 去重也不能单独承担平台永久逻辑 Run 身份。

## 同场景观测

本表的“未测”与“通过”都限定为候选探针，不表示当前 Temporal 产品集成的完成状态。

| 场景 | Temporal 1.32.0 / Server 1.31.2 | Prefect 3.8.5 | Hatchet SDK 1.40.0 / Engine 0.105.16 |
| --- | --- | --- | --- |
| 动态 schema、限定工具身份、并发 Run 隔离 | 通过，构造时注册稳定 DynamicToolset | 通过，稳定 DynamicToolset | 通过，自定义模型/工具 child 适配 |
| 分支并行、逐节点就绪 | 通过，E 在慢 C 完成前启动 | 通过，E 在慢 C 完成前完成 | 通过，E 在慢 C 完成前启动 |
| 已确认模型/工具恢复 | SIGKILL 后通过，未确认模型重试 | 同 Run 缓存通过，Automation 自动恢复另有通过证据 | 只中断 durable Worker 后通过，调用 Worker 保持运行，故障深度不同 |
| 成功兄弟节点恢复 | 已测通过 | 已测通过 | 恢复场景未包含 sibling，未测 |
| 新 Run 默认新鲜度 | 通过，独立历史 | 通过，SDK 缓存键包含 RUN_ID | 通过，无跨 Run 缓存 |
| 取消范围 | 直接活动节点、AgentWorkflow→模型 Activity；完整父子调用链未测 | 普通 sleep Flow 的 API Cancelling→Cancelled；Agent 调用未测 | 直接子任务取消通过；已测默认父→子传播未停止 |
| 总 deadline | 引擎超时停止活动调用；探针未覆盖重试组合 | 固定绝对 deadline 跨三次尝试通过 | 仅过期边界拒绝；完整生命周期未测 |
| 固定制品 | digest guard 与固定插件文件选择；跨核心版本路由未测 | 实际旧核心源码 loader/插件子进程；完整依赖闭包未测 | 仅存在性 guard；实际制品路由未测 |
| 启动重复投递 | namespace retention 内相同 Workflow ID 被拒绝 | deployment idempotency_key 返回同 Flow Run | TTL 内重复被拒绝 |
| 平台 Run/快照/outbox 原子性 | 候选探针均未覆盖平台事务与投递 | 同左 | 同左 |

“通过”只指表中列明的观测范围。尤其 Hatchet 探针正常退出表示成功完成观测，不能抹去报告中的取消失败；Prefect 基础探针未测自动恢复的结论由独立 Automation 探针补足。三个候选均未以 fake 制品 guard 代替完整 A10/A16。

三者的永久业务 Run 身份与事务 outbox 都由平台负责；Temporal `REJECT_DUPLICATE` 同样受 namespace retention 限制，不能把它描述成永久去重。探针故障范围不同，未测场景不构成候选不支持的证据。

## 实现与运行成本

- Temporal：官方 `TemporalDurability`；一个本地持久 dev server 和 Worker 即可运行探针，业务函数无需逐插件注册。工作流代码遵守确定性约束，动态工具集合必须在 Agent 构造时以稳定 ID 注册。产品中的固定核心 Worker 制品、MCP、outbox、调度和查询投影由 [`架构说明`](架构说明.md) 记录。
- Prefect：官方 `PrefectDurability`；server、Runner 和持久 task-result storage。需要明确 crash Automation、重试上限与失联检测；包含 Pydantic AI ContextVar 的 live Agent 对象无法直接 cloudpickle 注册，file-entrypoint deployment 实测可用。SQLite 探针记录四次锁冲突后由 SDK 重试完成；这不构成生产并发稳定性结论。
- Hatchet：本地 embedded engine 自带 PostgreSQL，另有 durable/call Worker。调用级适配代码由项目维护，需进一步补父子取消和长期身份策略。观测到 Worker 重新分配约二十九秒，不将单次时延当作性能排名。

探针运行形态和包含的进程不同，瞬时 RSS 不能用于三候选性能排名。本决策优先比较满足既定生命周期语义需要维护的代码和状态策略，没有虚构负载测试或持续运行成本数字。

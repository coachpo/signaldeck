# 工作流解耦方案

本方案已实施并合入 `main`，版本入口见[项目状态](../STATUS.md#工作流解耦2026-09-09)。D01–D06 均取得实际证据；原实施验收与 main 集成复验分别记录在下方。包解析、编译、Launch、Temporal DAG/Agent 和进程外插件继续承担原职责；本次改造的是任务发现、输入/结果展示合同及工作流数据分发，没有增加第二套工作流根或执行器。产品验收归[产品说明](产品说明.md#解耦验收)，模块边界归[架构说明](架构说明.md#工作流边界与已知偏差)。

## 设计定案

目录直接枚举已保存的 Package/Workflow，表单复用已有 schema/value 编解码和生成组件，结果消费冻结展示声明，预置 YAML 通过普通定义路径导入。原有四个示例保留为数据和回归场景，不能作为平台注册表。

不采用独立场景名单：它仍要求新增工作流修改 Core 或前端。不采用全量原始 JSON 作为唯一体验：它不能满足普通表单和正文/回执阅读。也不加载逐工作流 React/脚本：复杂业务页面已经由独立插件拥有。本次使用有限、闭合的数据声明，复用现有引用命名空间；不引入任意组件、HTML/CSS、计算表达式、网络访问或另一套条件求值。

| 契约 | 线格式及版本 |
| --- | --- |
| 包根 | 继续使用 `apiVersion: signaldeck.workflowPackage/v2`。 |
| Schema 注解 | 在需要注解的 **schema 节点**显式写 `x-signaldeck-schema: signaldeck.schema/2`；未标记仍为 schema/1。 |
| Workflow 展示 | 可选 `presentation`，必须带 `version: signaldeck.presentation/1`。 |
| 插件结果链接 | 工具可选 `resultLinks` 数组，每项必须带 `version: signaldeck.resultLink/1`；属于工具 contract digest。 |

新增的 Workflow `description`、`presentation` 和工具 `resultLinks` 在缺省时不进入序列化，不给旧定义自动添加字段。显式 `null` 不等于省略。包已有 canonical 默认值与排序规则保持；旧定义的固定 hash、嵌套序列化和旧插件 contract digest 由回归验证。

## 输入与标题

schema/1 继续拒绝 `default`、`examples`；schema/2 在原闭合子集上增加这两个注解。标记不向子节点隐式继承，每个带注解的节点须明确版本，便于该节点被单独作为映射/字段合同校验。`examples` 是数组，每个示例及 `default` 都必须符合其完整 schema；对象默认值同样受闭合字段、required 和嵌套约束约束。`default: null` 仅在对应 schema 接受 null 时合法，不能借默认值引入 nullable union。

```yaml
inputSchema:
  type: object
  properties:
    brief:
      type: string
      title: 核对说明
      description: 本次需要核对的内容
      x-signaldeck-schema: signaldeck.schema/2
      default: 待核对事项
      examples: [核对本周收件]
  required: [brief]
presentation:
  version: signaldeck.presentation/1
  title: {kind: input, ref: workflow.input.brief}
  inputHints:
    - {ref: workflow.input.brief, control: textarea, placeholder: 填写具体事项}
  sections: []
```

默认值只在创建新输入草稿时物化，并显示在实际提交的同一份参数中。已有值、常用配置、历史复用、计划参数和已应用 JSON 不补值；编辑兄弟字段或数组项不会补回省略字段。对象默认值按声明原样复制，不递归补充其内部未声明值。无默认值时的空白编辑模板不是服务端业务默认值。API 校验、准备、直接启动、重跑、调度与历史读取均不隐式补值。

字段标题/帮助取 schema title/description；任务名称取 Workflow name，缺省为 workflow key，说明取 Workflow description，未提供时回退包 description。服务名称取已保存配置，未知服务/scope 直接展示公开 ID/字段名。平台只保留自身状态、预算和协议术语。

`inputHints` 仅允许字符串字段的 `text`/`textarea` 和可选 placeholder，`ref` 使用 `workflow.input.<字段路径>`。标题使用 `{kind: input, ref: ...}` 或 `{kind: static, text: ...}`；输入引用必须是已声明的字符串。空白/不存在的输入标题回退冻结 Workflow name、包 name、workflow key；有效标题去除两端空白并截取 300 字符。历史列表的数据库搜索/排序与结果读取使用同一冻结选择语义，不扫描 title/question。

普通任务与计划使用同一个 `LaunchInputs`。不能转为普通对象表单的合法数组、标量、null 或复杂对象仍出现在目录，并可在普通模式完整编辑 JSON。结构编辑器的 presentation 和复杂 schema 使用显式应用的 JSON，与 YAML AST 共享单一定义；未应用草稿继续阻止保存/启动。

## 结果选择器

`presentation.sections` 是有序闭合声明，每项具有 `kind`、`label`、`ref` 和可选 `required`（缺省 false）。引用只能指向 `workflow.output` 或 `nodes.<node>.output` 及其 schema 中存在的字段/固定数组下标。编译验证引用和类型，不赋予业务字段任何隐含角色。

| kind | 引用类型/作用 |
| --- | --- |
| `markdown` | 字符串正文。 |
| `value`、`receipt` | 任意合法 JSON 值；回执标签由包声明。 |
| `sources` | 数组；条目仍是通用值。 |
| `dataTime` | 字符串；仅显示声明数据，不伪造时间。 |
| `notice` | 字符串或字符串数组，另需 `severity: info\|warning\|missing`。 |
| `link` | 已确认节点的输出选择；另需明确 `toolId` 和 `linkKey`。 |

结果只读取最终输出及成功节点/工具证据，不提升运行中或失败节点的模型文本。分节保留 node/evidence 身份，确认工具归属另保留 toolEvidenceId、operationId、pluginId；确定性 Agent 的公开输出即使经映射改名，仍由其确认工具操作拥有。通用产物也保留相应来源；内容相同而来源不同的证据不会被合并掉。

可选分节缺席不构成业务缺失。`required` 分节在运行终态仍无值时才列为缺失；告知、警告与缺失各自表达。正常条件跳过单列 `skipped`，执行失败/阻断/超时/取消单列 `executionIssues`。Run 状态、取消请求、缓存来源和逻辑操作 unknown 始终来自执行事实；unknown 优先显示，声明不能把它覆盖为成功。

`ResultRead.sections` 是通用阅读合同；附件 kind 仅保留 `artifact`，原 report/note 展示改为显式 receipt/link 分节，调用方不能再依赖旧业务附件类型。既有 `body`、`receipt`、`sources`、`dataTime` 仅从对应显式分节派生，不再按输出别名提取。大值若已存为 `$artifact`，投影保留产物引用和 `deferredSections`，页面可读取/下载确认内容，不把未展开的字段或链接误报为业务缺失。它不为展示自动读取插件，也不把大产物重新塞入普通结果响应。

## 插件链接

Workflow 链接分节明确选择节点、限定工具及 `linkKey`。工具的 `resultLinks` 线格式、相对路径/参数约束和发布摘要由[插件接入合同](writing-extensions.md#声明结果页面链接)维护；这里定义 Workflow 的选择、绑定和读取语义。

v1 每个链接分节选择该节点、该工具最近完成的一次 succeeded 调用，按 `(finishedAt（缺省 Run.createdAt）, evidenceId)` 降序确定；同时间以证据 ID 降序决胜，较新的失败调用不参与。`ref` 确定节点及公开值的可用性，URL 只绑定所选工具确认输出，不代表模型对多条记录的额外选择；其他调用仍完整保留在技术证据中。

链接取该节点该工具的确认输出，保留实际操作归属，不按节点字段相似性猜工具身份。Core 只做通用链接绑定，不解释插件路由或参数的业务含义。

编译检查节点工具授权；准备和 Launch 在实际冻结发布中检查 linkKey 及 pageUrl，缺失分别返回 `presentation_link_unavailable`、`presentation_page_unavailable`。分节可选不表示错误合同可被接受；历史读取使用 Run 冻结的发布及已确认输出，不重新解析当前插件。

## 独立数据导入与分发

`POST /api/workflow-packages/import` 接受 `{sources: [{name?, manifestSource}], mode: missing_only|update}`，缺省 missing_only，最多 100 项。返回 items，逐项报告 `created`、`preserved`、`updated` 或 `error` 与源码诊断。普通保存与导入使用相同 parser、compiler、canonical source 和不可变修订检查。

`PlatformStore.import_package` 与普通保存锁定同一 package key。在事务内判断指针是否存在，missing_only 对已有 key 直接保留，不通过 GET 后 save 实现。missing-only 导入与普通保存竞争时，仍不得覆盖操作者已保存修订。显式 update 按普通保存语义推进当前指针；同 hash 不新增另一份内容修订。事务锁不等于基于预期修订的冲突检测，update 不提供 missing-only 的保留保证。

直接运行 Core 时，`SIGNALDECK_WORKFLOW_DATA_DIR` 未设置或为空即不导入；空目录/缺失目录同样正常启动。可选目录中的 YAML 逐项导入，坏文件不阻止通用 API 或其他包。启动导入结果保存在本进程的 `app.state.workflow_imports`；需要逐项客户端诊断时使用导入 API。

本地组合镜像把 YAML 放在 `/opt/signaldeck/workflows`，在 `backend/app` 可执行 closure 外。Compose 默认把 `SIGNALDECK_WORKFLOW_DATA_SOURCE`（缺省 `./demo`）只读挂载到该路径，因此只更新数据无需重建镜像；设置 `SIGNALDECK_WORKFLOW_DATA_DIR=''` 可禁用安装，或把 source 指向现有空目录。已有 key 不随重启升级，需要显式普通更新。

`demo/sync_seeds.py` 只生成 `demo/contracts.json`，不再生成 Python 中的 YAML。Core digest 仍覆盖自己的代码/依赖清单，包 hash 单独冻结数据；YAML-only 修改不会改变 Core digest。历史 Core bundle 继续按其原 manifest 保留核验，即使原包内包含内嵌种子 Python，也不改写或缩小旧制品。

## 历史与四场景影响

无 presentation 的历史包仍可编译、启动、重跑，并按原快照保留输入、输出、插件发布、资源及 Core 身份。阅读改用通用最终值、确认节点/工具值、文本/JSON 产物和技术证据；原先由 title/question 猜出的标题、由 content/text/markdown 猜出的正文、由 sources/quotes/warnings 猜出的来源/缺失、由 reportId 或 collection/id 猜出的业务附件和报告深链接不再产生。确认结果没有丢失，也不读取当前包替旧运行添加解释。

四个示例的名称、标签、提示、默认值、正文和回执选择已经写入 YAML。市场研究 includeRisk 默认 true；false 时风险分支正常跳过，可选风险分节缺席，不再由 Core 代写“缺少风险分析”的业务结论。Finance/Oracle 的业务来源或告警，只有声明选中或业务正文表达的部分进入普通阅读，其余确认值仍在技术证据中。

实现及 main 集成都没有转换、切换、清理或重建任何现有实例。若未来要求旧记录保持原先专用呈现，应先针对具体实例核对快照、确认值和所需声明，准备独立、可审查的转换方案；不能通过回写旧快照或长期业务白名单实现。本次通用回退本身不需要数据转换。

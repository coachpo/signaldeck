# 投研升级实施合同与验证

## 范围与状态

本文件承接 2026-09-16「分析 SignalDeck 投研信号」会话的三批建议：可信个股报告、可选信号增强、轻量监测复盘。先完成前置修复，再在 `6f972043` main 基线上实现三批主流程；**实现及分层验证见文末**。范围为美股、数周至数月的个人研究，默认使用现有 NVDA 示例，回归另用 MSFT 防止适配器只适合一个财年。

原实施依据是当时的 [demo 说明](../../demo/README.md)、[插件制品](../../plugins/README.md)、源码及本页验证记录。此前 NVDA 内容复核发现两项研究错误：来源链接在多次摘要中丢失；74%±50 基点的毛利率指引被误写成低于 74% 即落空。原报告属于历史证据，不修改或覆盖。本轮把这两个例子纳入第一批验收，不以模型提示词修改冒充确定性校验已经实现。

本页的示例合同、hash 同步要求及测试文件名是原实施版本的规划和验证事实，不构成当前平台开发、分发或测试依赖；历史路径可能已删除。当前边界见[产品解耦原则](../产品说明.md#工作流与平台解耦原则)，平台和插件使用独立 fixture 验证各自公开契约。

产品与数据权限仍由 [STATUS](../../STATUS.md) 和[产品说明](../产品说明.md)决定。下文的拟议字段与工具属于实施设计，不能据此声称当前发布已支持它们。没有新建 GOAL、排期或审批流程。

## 第一批：已确定的实施合同

### 数据、时间与证据

第一条真实财务链路采用 SEC submissions + companyfacts，并按 accession 关联原始申报；Finance 负责财务字段选择和计算，Oracle 负责申报/官方原文采集，YAML 负责明确的步骤与传值。两个插件通过公开值合同交换信息，不导入对方私有模块、不读 Core 表；SEC 请求各自使用部署配置。现有行情与新闻 provider 继续复用，不同时开发多个财务供应商。

[SEC 官方 API 说明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)确认 companyfacts 面向整家申报实体的标准 taxonomy。第一版覆盖收入、毛利/营业利润/净利润、经营现金流、资本开支、现金、债务及股数；分部、自定义 taxonomy 和经营解释通过原文摘录补充。不得假设 XBRL API 覆盖公司全部披露。

Finance 在现有 `fundamentals_lookup` 的新发布中增加显式截止与逐事实出处合同，保留原工具身份及既有可省略字段语义；生产者、工具 descriptor、mapper、消费者及 YAML 一起演进。现有 `periodEnd` / `asOf` 本身不足以表达以下信息。证据以闭合、带版本的对象定义，不能用任意 metadata 字典替代：

| 对象 | 必要信息与规则 |
| --- | --- |
| 研究范围 | `symbol`、CIK、`asOfDate`、`cutoffAt`、`timezone`、研究期限；日期按 America/New_York 下一天零点的排他上界转 UTC，正确处理夏令时。实时研究的上界不能晚于冻结采集时刻。 |
| 来源 | 稳定 `sourceId`、来源类型、原始 URL、文档摘要、`retrievedAt`；公开时间与观察期间分别存放，未知就缺省并附原因，不互相填充。 |
| 事实 | 稳定 `evidenceId`、`sourceId`、指标概念/taxonomy/tag、十进制字符串 `value`、`unit`、币种、起止期间或时点、财年/财季、accession、form、filed/accepted 时间、原文定位与摘录。 |
| 派生值 | 公式版本、运算数 evidenceIds、结果单位、舍入规则；不是新的独立来源。计算失败、币种冲突、零分母或缺项时返回缺口，不填零。 |
| 论断 | 事实/推论/用户未核实材料三类分开，引用 evidenceIds；每个事实性数字须有可复算证据。标题或摘要不能升级为“已读原文”。 |
| 阈值 | `basis` 明确为公司指引、历史分布或研究假设；值、单位、区间、期间、比较方向及 evidenceIds 齐全。研究假设附理由，不自动变成公司指引。 |

逐项截止筛选依据公开/接受时间，不依据财务期末。只知 SEC filingDate 时按日期精度处理，缺精确时刻不能用于声称日内可得；有 accepted 时间时按完整时间核验。相同事实优先选截止前可见的适用修订，保留被替代版本关系；不能用当前 companyfacts 中截止后修订覆盖历史。当前 API 不足以证实历史可得性的来源标为限制。

季度与年度根据实际期间判定，不以 `fy` / `fp` 或 `frame` 单独认定。现金流累计数与单季数分开；Q4 可由同口径 FY 减前三季累计推导，TTM 仅由四个连续、无重叠同口径季度组成。资产负债为时点值，流量为期间值；期末股数和加权平均/稀释股数不可混用。至少覆盖不同财年、53 周财年、修订、单位冲突、截止后披露和缺项边界。

估值只在价格时点、货币和财务口径相容时计算；EV 的现金/债务选择、FCF 的资本开支符号、每股值的股数类型随公式留证。缺一致预期时不判断“超预期”，缺必要估值输入时允许“证据不足”。

### 原文与报告

原文先支持 SEC 10-K/10-Q/8-K 及其相关附件、公司 IR 和研究问题明确指定的官方政策文档。必须保留 URL、文档标识、取得时间、正文摘要、定位（章节/页码/段落）和摘录；无法取得正文、仅有摘要、扫描件或不支持格式时如实告知。实现时按真实样本选择现有解析依赖，首版不建立通用爬虫或全量电话会库。

证据由采集节点单独输出，后续分析、辩论、风险和裁决均显式引用同一份结构化集合，不能只把它埋入各自 6000 字以内的 content。Finance 确定性校验引用和数值/单位/阈值关系，从校验通过的结构化论断生成事实、数值、阈值段落及来源附录；模型负责定性解释。模型自由 content 中出现的额外数值或阈值断言不能继承旁边结构化字段的“已验证”状态，必须转为可验证论断或标为未核实并使报告降级。YAML 保存与展示该工具返回的同一份规范正文，不再保存另一份未经核对的模型 content。业务校验失败时返回具体缺口或证据不足，不保存一份冒充验证通过的报告。普通 `reports_create` 仍服务任意报告，研究校验通过专用公开工具/显式参数路径进入，不在 Core 或通用报告保存中推断内容类型。

验收必须重现：73.8% 在 73.5%–74.5% 指引内，不能标成指引落空；74% 若是研究阈值必须标明 basis。自动采集来源经过所有研究节点后仍有原 URL、公开时间与定位；同源转载与重复工具调用不增加独立证据数。保存正文、工作流输出和下载三者一致。

## 第二批：可选信号的启用条件

Reddit、StockTwits、Form 4 复用现有工具；样本数量、请求窗口、实际覆盖、日期、来源及失败告知随证据输出。社交热度只形成待核查假设。Reddit/StockTwits 的有限当前搜索不是历史完整档案；当前投票/评论统计不能被归作过去某个截止时刻的统计。

预测市场首版最多跟踪每个研究对象三个显式事件，输入保留 venue、event/contract ID、研究假设及关联理由。Oracle 新合同需补充结算规则/来源、规则版本或摘要、到期/结算状态、报价时间、outcome/token 身份、bid/ask、成交量与流动性；这些缺失时不能解释概率变化。基线只用同一合约、同一 outcome、可比报价类型及同一规则版本。规则变化、关闭或时间过期独立报告。[Polymarket 官方市场数据说明](https://docs.polymarket.com/market-data/prices-order-books)提供盘口与价格历史接口；实现优先用官方历史或显式保存快照，不建设全量历史库。

新研究流程默认不调用期权，只有显式财报事件研究启用。届时锁定 Oracle 的可选 yfinance 依赖及锁文件，保持默认制品无该依赖的明确降级，构建可选制品并实测一个标的/到期日。只把实际可得的盘口/IV/持仓量作为证据；不补造 Greeks 或历史报价。利率、汇率、商品、CFTC 同样按研究对象敞口选择；Treasury 平均融资利率不替代无风险期限收益率，FRED 当前观测不替代历史公布版本。

对照采用相同标的、截止、基础证据快照、研究问题、模型和预算，分别不启用/启用可选来源；保留新增独立事实、具体假设变化、来源失败、耗时与调用/用量。只有存在可靠价格配置时计算费用，不能编造成本。可选源 403、429、超时、空结果或关键元数据不足时应降级完成基础研究，并明确增强部分缺失。

## 第三批：显式监测与复盘

使用现有 Temporal schedules 与条件 DAG，新增业务状态全部由 Finance 持有。创建独立监测 Workflow，保留现有手动 `previousReport` 的语义。监测输入为 `monitorKey`、symbol、结构化研究范围、规则版本、选定来源/事件及新鲜度要求；不让任务日期固定在 schedule 参数中。

每次开始通过 Finance 的幂等写工具冻结 `cutoffAt` 和本次业务快照身份；使用已有 MCP invocation/operation 身份恢复同一次调用。工具 effect 必须声明 write，并复用独立插件 operation journal。在首次成功事务提交时冻结当前时间：提交后响应丢失，同 operation 的重放返回原 cutoffAt；提交前已确认回滚则尚无有效快照，允许重取时间。验收覆盖这两种边界，不承诺现有 journal 保存第一次网络尝试的时刻。新定时触发创建新的 operation 和截止。

快照保存 `snapshotId`、`monitorKey`、symbol、scopeHash、ruleVersion、cutoffAt、证据摘要、完整性/新鲜度、可选 reportId/digest、前一基线 ID。scopeHash 包含 symbol/CIK、研究期限/问题、选定来源/事件身份、规则与新鲜度设置，排除每次变化的 cutoffAt/asOfDate/retrievedAt/snapshotId；否则每日都会错误地变成无基线。比较工具在 Finance 内按准确范围和规则版本选取**早于本次截止**的上一有效快照；不以最近一份任意报告作为基线。完整证据留插件存储，公开工具返回有界的变化条目和精确引用，不把整份历史报告塞入 6000 字输入。

状态至少区分：无基线、无实质变化、资料无效/过期、有实质变化。首次或范围/规则变更先建立可用基线；无变化保存新的有效观察并跳过深研究；资料无效不替代有效基线；有变化才执行深研究，并区分新增事实、事实更正和研究假设变化。规则版本变化不冒充市场变化。

首版实质变化规则：新增相关官方披露或适用事实修订触发；行情、社交计数和预测报价只有达到输入中显式配置的指标/方向/阈值时才触发，未配置就只记录。retrievedAt、返回排序、重复抓取以及模型措辞/观点的变化不触发。必需证据不足或过期优先判资料无效，可选来源失败独立告知，不伪造“无变化”；无变化结论只适用于已满足新鲜度的选定证据范围。

观察快照与深研究报告状态分开：一次采集完整的观察可以有效，即使其后深研究失败，报告状态仍须失败；失败的观察不能成为基线。基线指针通过事务及版本比较单调推进，较晚完成的旧截止不覆盖新截止；快照唯一键/operation 去重避免并发重复。最终报告绑定明确观察快照，不能读取执行中变化的“latest”。这些义务已落实到 Finance 的独立快照/头指针表及监测工具；实现不修改 Core 的调度语义。

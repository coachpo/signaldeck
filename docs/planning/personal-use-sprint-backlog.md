# SignalDeck 个人使用优化 Sprint Backlog

## 基线与共同约定

上游权威为 [个人使用优化实施计划](personal-use-implementation-plan.md)，版本日期2026-09-10，源码基线 `5a993684eb35f655d46cffbec2c0a3f73c55fd4e`。需求 `pu-r01–pu-r14`、工作包 `pu-wp01–pu-wp09`、验收 `pu-a01–pu-a11` 和未决条件 `pu-o01–pu-o06` 均由上游定义。本文件只分解任务、依赖、建议迭代位置与完成条件，不扩大上游范围。

2026-09-10 已按用户开发请求完成 PU-S1 的4项实现及本阶段联合验收；其交付与验收见[PU-S1 验证记录](personal-use-s1-verification.md)。PU-S2–S6 的19项任务及最终共同验收现已完成，实际版本、命令、证据和边界见[共同验收记录](personal-use-verification.md)。具体人员未分配；前端/后端/Notes插件/集成验证是可由同一执行者兼任的工程角色，不构成人员或并行承诺。按“一条可验证增量”控制拆分；Sprint编号表示建议顺序，没有固定周数、日期或工时。本轮 PU-S1–S6 实施及有限真实模型验收使用已提供的授权；未排期候选仍未启动。

所有任务的验收责任方均为所在 Sprint 的集成验证角色（人员未分配）；各任务主责向对应 `pu-sN-verify` 交付产物、实际版本、检查结果和必要证据。下游只消费明确的可用输出，不等整个工作包完成。每项的“输入已具备”仅说明可以开展设计/实现，不表示人员和环境已安排。

共同完成条件：交付限定范围内实现、必要回归与唯一权威文档/机器合同同步；执行 [CONTRIBUTING](../../CONTRIBUTING.md#检查测试与构建) 和最近子树指南中的适用检查，最后 `git diff --check`。前端使用现有 Vitest/Playwright，后端使用现有 pytest/静态检查；界面变更附适用四宽度与键盘验证。改 demo 才核对 `demo/contracts.json`、外部导入及 YAML-only digest；改根 Dockerfile 才补根镜像构建，不扩大依赖或测试基础设施。

验证条件 **L/B/M/H** 继承实施计划。每个 Sprint 都做自身联合验证，不能全部推迟到最后。固定错误或历史样本可以验证分支，但实际工作流成功必须使用真实模型回复；模型额度不足只保留 M 项未完成，不暂停无关本地工作，也不通过模拟成功关闭该条件。真实验收不需要真人参与。

## 建议 Sprint 安排

| Sprint | 交付目标与用户增量 | 安排依据及容量假设 |
|---|---|---|
| PU-S1 连接、正文与诊断 | 首次接入不被误导；正文结构正常；模型最近调用与失败原因可理解 | 5项，中等：两项局部UI与一条后端→前端诊断链；当前代码/证据足够细化，M仍有额度条件 |
| PU-S2 可阅读、可带走的结果 | 普通页减少重复信息；确认正文可复制/导出Markdown，历史/局部结果保持真实语义 | 3项，中等：复用S1正文与已有冻结结果合同，不增加报告管理系统 |
| PU-S3 看懂和控制模型消耗 | 本次/今日用量与耗时可核对；单次输出上限独立配置，旧包/快照不漂移 | 4项，中等至较大：用量投影与预算合同两路独立，最终合并UI与真实验证 |
| PU-S4 结果整理与站内处理 | 收藏、已读、备注可保存；完成、失败、unknown及无Run的fire失败可发现 | 4项，较大：附属存储和状态变化身份须先明确，无外部通知渠道 |
| PU-S5 草稿恢复与结果比较 | 刷新可恢复显式草稿；两次结果可并排检查差异 | 4项，较大：草稿与比较两路独立，比较只依赖S2确认内容规则，无模型摘要 |
| PU-S6 Notes资料工作区与共同验收 | 找回已积累笔记，新结果直达Notes页面，主体改进形成整体闭环 | 4项，中等加整合：只读插件页面不等其他Sprint全完；最终联合验收才依赖主体输出 |

推荐先交付 PU-S1–S4。PU-S5/PU-S6 可以按使用频率调整先后；Notes API和页面、用量读投影及草稿合同都可在各自输入具备后提前开展。未排期候选不构成以上Sprint的前置，也不以末尾“整合”名义混入主体完成范围。

## PU-S1 — 修正接入与正文，让失败可诊断

顺序：`pu-connect-feedback`、`pu-markdown`、`pu-model-diagnostics` 可独立开始；诊断安全字段/样例交接后启动 `pu-diagnostic-ui`；五态、排版与诊断联通后由 `pu-s1-verify` 汇总。共同验收为 pu-a01/02/03：在 L+B 中补连接并得到可读结果，M验证真实模型观察，固定错误回归核对分类与脱敏。容量以这条闭环为限，不夹带草稿/存储新功能。

### pu-connect-feedback — 修正连接预设状态

- 来源/主责：pu-wp01，pu-r01，pu-a01；前端，后端协作，交给S1汇总和后续普通信息披露。
- 产物/边界：调整 `task-connections.tsx` 的加载、失败、无候选、待选择和已选择状态；有候选未选时显示选择提示。保留显式业务范围确认、凭据清空和输入，不自动选首项。
- 前置/就绪：当前预设接口与已复现条件可直接开始；接口不变，无业务决策缺口。实际连接需L中的Notes发布和资源预设。
- 完成/验证：五态互斥准确；就地保存成功后原字段与准备校验保持；无预设不冒充已部署。现有组件用例加真实L+B连接操作，交付状态截图及执行回执；验收归S1集成验证。

### pu-markdown — 统一结果正文排版

- 来源/主责：pu-wp01，pu-r02，pu-a02；前端，交给S2导出/阅读与S5比较。
- 产物/边界：声明结果、历史正文和文本/JSON附件中适用的Markdown共用轻量样式；覆盖标题、段落、OL/UL、表格、代码、链接。JSON仍按JSON阅读，不把所有值当Markdown。
- 前置/就绪：现有组件、主题和真实清单观察可直接开始；无需模型额度或新的编辑协议。
- 完成/验证：列表标记可见、原文内容不变、长表格/代码受控滚动，375/768/1024/1440及键盘可读。B的组件与渲染检查、真实确认正文截图；链接与未完成文本提升边界保持，验收归S1。

### pu-model-diagnostics — 安全错误与模型观察投影

- 来源/主责：pu-wp02，pu-r03，pu-a03；后端，前端协作；交接给 `pu-diagnostic-ui`、S3用量和S4处理入口。
- 产物/边界：在现有模型适配器建立已知安全错误类别与未知回退；只保存允许字段，原异常不透传。按资源与冻结配置/凭据版本身份投影模型最近确认观察、时间和错误类别；不在prepare/list读取中探测或调用模型。
- 前置/就绪：已有model/attempt证据与HTTP归一化可开始；先交接类别、身份匹配和无记录样例，UI可据该子集开发，不等待整个后端完成。
- 完成/验证：凭据更新或换endpoint/model后不把旧观察冒充新连接状态；失败、无usage、未知状态安全可读；旧400记录不补写猜测原因。聚焦pytest用安全错误样本覆盖额度/认证/限流/模型/输入/未知与恶意回显，L+M补真实成功及工具调用记录。交付API样例、回归结果和证据ID；额度条件pu-o01只影响M验收。

### pu-diagnostic-ui — 在任务、结果和安排中提供处理方向

- 来源/主责：pu-wp02，pu-r03，pu-a03；前端，后端协作；交给S1及S4站内处理。
- 产物/边界：准备/已连接服务显示实际最近模型观察；结果及fire失败显示安全原因、明确处理方向和技术证据入口。原始错误码可展开，配置就绪不改称在线；无Run的启动失败也可显示原因。
- 前置/就绪：消费 `pu-model-diagnostics` 的安全字段、观察绑定与样例即可开始；最终联通等实际API，不依赖S3用量页面。
- 完成/验证：已知额度错误能看出需检查额度，认证错误不误导为业务缺资料；未知仍明确未知；输入与重跑身份保留，不自动重试/换账户。B组件覆盖和L真实成功/失败导航，M真实观察与原错误样本分开记录；交付截图/跳转/参数保留证据，验收归S1。

### pu-s1-verify — 接入、阅读与诊断联合验收

- 来源/主责：pu-wp09，pu-r01/r02/r03，pu-a01/02/03/11；集成验证，各产物角色协作。
- 前置：上述四项可运行输出；L+B；真实模型部分需pu-o01满足M。测试边界准备可提前，实际验收不先行宣告通过。
- 产物/完成：从缺连接开始执行Notes保存、真实整理和模型主动工具调用，检查列表排版、输入/绑定保真、最近观察与安全失败说明；同时使用独立错误样本验证分类。保留原定时400与后续配额复核是不同请求这一事实，不补造历史原因。
- 验证/证据：聚焦后端/前端检查、相关tasks/resources E2E和适用静态/构建门禁；关联实际版本、Run/operation与截图，记录M是否完成，并同步已验证行为的权威文档。只关闭实际通过的子项；交给S2共享正文和S3诊断合同。

## PU-S2 — 结果易读、可复制和导出

顺序：S1正文组件及现行冻结选择规则可用后，`pu-result-disclosure` 与 `pu-result-export` 独立开发，`pu-s2-verify` 联合。验收 pu-a04 加 a01/a02受影响回归；L+B+H覆盖成功、局部、unknown、无声明和大产物，真正离线读取不由UI占位模拟。容量不包含PDF引擎或Finance模板改造。

### pu-result-disclosure — 收拢重复与技术信息

- 来源/主责：pu-wp01，pu-r01/r02，pu-a01/02/04；前端，后端协作；接收 `pu-markdown`，交给导出与比较入口。
- 产物/边界：普通准备页优先连接名称、影响任务的业务范围和变更；技术配置折叠但未知scope字段仍可见；结果正文优先，原始回执对象与完整输入可展开，状态/来源/unknown不折叠隐藏。
- 前置/就绪：现有sections、safe settings与changedBindings已可用；最终样式依赖 `pu-markdown`。不按text/reportId/collection等业务键去重；本轮保留通用原值，不扩展展示合同。
- 完成/验证：模式往返无写操作/草稿丢失；关键绑定变化无需展开即可察觉；真实窄屏减少重复正文，完整证据和Finance入口保留。B截图/键盘与L读取、取消/unknown回归，验收归S2。

### pu-result-export — 复制确认正文并导出Markdown

- 来源/主责：pu-wp03，pu-r04，pu-a04；前端，后端审核安全投影，Finance协作核验既有下载；交给S5比较。
- 产物/边界：确定并实现基于冻结sections/确认产物的可交付内容选择、正文复制和Markdown文件；保留必要状态、来源、时间。无正文给明确反馈，剪贴板/下载失败有可恢复操作；Finance原下载不被替换。
- 前置/就绪：当前安全结果合同可先核对；内容选择规则先交给比较任务，最终阅读效果接 `pu-markdown`。不读业务私有表，不从失败节点提取未确认模型正文；大产物若待展开需显式选择/读取，不能静默漏内容。
- 完成/验证：L+B+H核对成功/局部/unknown/取消/无声明/大产物；插件与引擎离线后确认内容仍能导出；文件对照原内容和来源，不出现凭据。交付选择规则、文件与回归证据，验收归S2。

### pu-s2-verify — 阅读与成品交付联合验收

- 来源/主责：pu-wp09，pu-r01/r02/r04，pu-a04/11；集成验证，前后端和Finance协作。
- 前置：两项S2功能与S1共享正文实际输出；L+B+H。可复用同实现版本的真实模型成功产物，不为纯排版重复消耗模型额度。
- 产物/完成：普通模式打开结果、查看关键状态、展开原始值、复制/下载、回到历史筛选；确认结果与文件一致，Finance仍拥有格式/报告，未知效果与局部完成没有被成品化掩盖。
- 验证/证据：结果/历史组件、对应跨栈与真实双离线相关回归、受影响门禁；提交实际文件、截图、状态及冻结证据对照，同步文档；交给S5确认内容合同。

## PU-S3 — 用量可见，输出上限可控

顺序：`pu-usage-projection` 与 `pu-budget-contract` 可并行；各自契约子集就绪后 `pu-model-controls` 接线；`pu-s3-verify` 汇总。pu-a05使用L+B+M，额度不足不阻塞聚合和旧hash回归。相对复杂度来自协议/冻结/执行边界，不能只交一个数字面板便认定完成。

### pu-usage-projection — 从调用证据汇总用量

- 来源/主责：pu-wp04，pu-r05，pu-a05；后端，前端协作；向模型控件交付只读API。
- 产物/边界：每Run和指定当地日的输入/输出token、模型请求及耗时摘要，标识缺usage/未确认调用；按逻辑调用身份去重确认数据，说明失败网络尝试的计量覆盖，不宣称供应商账单或余额。
- 前置/就绪：既有model/attempt结构可开始；错误解释消费S1安全类别但不阻塞计量主体。依据pu-o03说明是否需要新增只读索引/投影，不引入独立计费状态机。
- 完成/验证：成功、失败、重试、同Run恢复、缓存、跨模型和日界线可对账；缺值为未知，不把多个引用的同一usage重复相加。pytest对账、L历史和M实际usage记录；交付字段/查询样例及对账结果，验收归S3。

### pu-budget-contract — 独立单次输出上限及执行映射

- 来源/主责：pu-wp04，pu-r05，pu-a05；后端，前端与定义维护协作；交给 `pu-model-controls`。
- 产物/边界：解决pu-o02，设计闭合、版本明确且不补入旧定义的可选单次输出上限；实现解析/诊断、序列化/hash、冻结、chat_completions与responses映射及实际限制。总token、请求次数、deadline继续独立有效。
- 前置/就绪：当前Budget与模型设置可开始设计；先交接新字段与省略/边界样例。不是放宽JSON Schema，不默认给旧包改值；若需现有数据转换，先交付具体影响与隔离验证，不操作原实例。
- 完成/验证：省略字段时旧定义hash/执行语义不变；明确配置时请求输出上限不超过定义与剩余预算边界；配置变化只影响新Run；真实模型不足/截断给真实终态。聚焦parser/compiler/snapshot与两适配测试、L+M请求证据；不以这项改造声称修复上游账户额度。验收归S3。

### pu-model-controls — 显示用量与预算操作

- 来源/主责：pu-wp04，pu-r05，pu-a05；前端，后端协作。
- 产物/边界：结果/适当的设置入口显示本次与今日用量、耗时、缺值说明；现有专家Agent预算编辑增加明确的输出上限，普通准备显示关键有效上限。不加入余额猜测、价格目录、自动探测或自动换模型。
- 前置/就绪：用量API与预算字段样例分别解锁对应UI；最终整合依赖两者实际输出及S1诊断UI。未提供价格不是阻塞条件，因为本项不做费用账单。
- 完成/验证：当地日界线一致、unknown不显示0、模式切换不改预算；编辑保存再启动可在冻结设置核对上限，历史保持旧值。B组件/流程及L+M调用对账，交付截图和设置→请求→usage证据，验收归S3。

### pu-s3-verify — 计量与预算联合验收

- 来源/主责：pu-wp09，pu-r05，pu-a05/11；集成验证，前后端协作。
- 前置：三项S3输出；L+B、旧hash/恢复样本，以及M真实接口/可用额度。没有responses真实模型时，两适配映射回归与chat真实成功须分开说明，不宣称双协议真实供应商验收。
- 产物/完成：核对预算编辑、新Run冻结、真实请求和用量摘要；重复读取/恢复不重复统计，缺usage/失败覆盖可理解，旧包无漂移。共享回归只在同实现版本且覆盖未失效时复用。
- 验证/证据：受影响A03/A07/A10/A11/A14及定义/运行门禁、实际usage对账和界面证据；同步执行/数据/API文档。M不满足时保留真实验收未完成，独立已通过项仍可交接。

## PU-S4 — 结果整理与站内待处理

顺序：`pu-result-metadata` 先给附属记录与冲突约定；`pu-result-organizer` 和 `pu-attention-inbox` 消费可用子集独立开展；S1错误类别供处理方向。pu-s4-verify联合验收pu-a06/07，包含无Run的fire失败、自然定时成功及浏览器关闭后重新打开。容量只含站内能力，不含浏览器推送或邮件/聊天外发。

### pu-result-metadata — 独立保存个人结果标记

- 来源/主责：pu-wp05，pu-r06，pu-a06；后端，前端协作；交付给整理页和站内处理。
- 产物/边界：收藏、已读、个人备注的独立附属记录与精确更新API，定义多窗口冲突/不覆盖其他字段的规则；只引用Run身份，不改原Run/spec/output。默认旧记录无标记；新增表/数据路径按pu-o03说明。
- 前置/就绪：现有Run查询和历史身份足够开始；先交接字段、默认值、冲突和读取样例，不要求整理页先完成。

### pu-draft-contract — 服务端草稿与启动身份合同

### pu-draft-ui — 保存、恢复与冲突处理

### pu-result-compare — 固定两次结果并呈现文本差异

## 规划基线

- 方案依据：[制定简化版 APP 操作方案](thread://01a07ee4-858e-7e80-b6f0-38be4e4150e1?hostId=local) 的最终答复；用户于 2026-09-08 在本次任务中接受该方案。该会话方案直接作为上游依据，不另建一份实施方案或重新冻结目标。
- 完成基线：[设置冻结迭代目标为 GOAL](thread://01a07d8f-8ae3-7641-b38e-7c5784cb9b70?hostId=local) 的最终两轮结果，以及当前 [STATUS.md](../../STATUS.md)。SD-TARGET-001 的实现提交为 `7285cecd274f2ac5416aa5d9d963517e845867ce`，文档整合提交及本清单源码基线为 `f7ced2f35cae20ab37e94acc9a89007a49143d10`。
- 基线核对日期：2026-09-08。读取时工作区干净；原方案中的“当前未提交实现”已被上述提交替代。原 `docs/迭代目标.md` 已删除，以现行[产品说明](../产品说明.md)、[架构说明](../架构说明.md)和[开发规范](../开发规范.md)承接已实现合同。
- 本次只落盘 Sprint 清单。下面的任务均为待办，检查方法与预期证据均是将来交付要求；不表示本轮已实现、已验收、已派发任务或已创建 GOAL。

## Sprint 安排与共同完成条件

| Sprint | 交付目标与可用增量 | 安排依据与可启动条件 |
| --- | --- | --- |
| S1 | 形成任务/结果/设置骨架，已配置用户可用普通表单启动“保存原文”并找到本次回执 | 先交付最小日常闭环；契约梳理与视觉规则可立即开始 |
| S2 | 四个首批场景可用；缺连接就地修复；研究结果正文和业务异常可读 | 使用 S1 的任务展示约定；结果契约和连接契约可独立准备 |
| S3 | 历史易查，重跑与改输入清楚分离，常用输入可保存复用；Finance 可直接使用已有格式 | 需要 S2 的结果关联和有效设置约定；不依赖 S4 全部完成 |
| S4 | 从任务/结果创建重复安排，可靠展示时区和下次执行，管理暂停与运行 | 时间语义核对可从 S1 开始；表单集成依赖 S1/S2/S3 指定输出 |
| S5 | 专家制作、资源/插件和诊断完整好用，两种模式无损往返 | 编辑器改造在 S1 约定明确后即可开始；最终整合需要 S3/S4 的复杂输入和计划 |
| S6 | 所有路径在实际本地栈联通，完成故障回归、视觉检查和无讲解用户验收 | 工程整合依赖各功能输出；用户验收另需参与者和可用业务服务 |

每个 Sprint 按“一条可验收闭环优先”的容量假设安排；前端、后端、插件角色只是责任接口。文中明确的前置输出决定启动顺序，Sprint 编号不构成整包串行屏障。可先用固定样本开发独立组件，但样本或 mock 完成不能关闭后续真实集成任务。

以下规则适用于每个任务，任务条目补充其具体条件：

- 责任角色为该任务实现与证据交付责任人；接收方为下游任务责任角色。工程验收由该 Sprint 的集成验收角色承担，人员未分配；产品体验验收由目标普通用户参与，产品验收角色负责结论，人员未分配。
- 每项完成都需交付相关代码、真实缺陷回归和必要的现行文档/契约同步。预期证据包括对应提交或工作区版本、检查命令与结果；界面任务附相应场景截图/操作记录，跨栈任务附 Run、产物或 Schedule/fire 关联记录。证据不得含凭据。
- 先运行已有的聚焦检查，再按 [CONTRIBUTING.md](../../CONTRIBUTING.md#检查测试与构建)执行受影响范围的必需门禁和 `git diff --check`。前端包含 lint/typecheck/test/build，路由与跨栈变化补 E2E；后端包含相应静态检查及 pytest。修改 demo 时同步 seeds/contracts 并运行示例合同测试。根 Dockerfile 如受影响才增加根镜像构建。
- 组件验证使用现有 Vitest；后端与跨栈测试用隔离 PostgreSQL、规定版本 Temporal、dispatcher、固定制品 worker 及受控 provider。具体环境遵循贡献指南，不能把现有实例当临时测试库。
- “可开始”仅表示已有输入足以开展工作，不代表人员/运行环境已分配。未另外列出的业务决策缺口为无；技术选型与具体接口字段由相关契约任务验证，不能据占位数据认定完成。

## S1 — 普通操作骨架与首个闭环

顺序：`sd-ux-contracts` 与 `sd-ux-shell` 的设计规则可同时开始；壳层模式语义采用前者的可用子集。随后交付 `sd-ux-task-form`，再完成 `sd-ux-capture`。容量优先保证保存原文闭环，不要求本 Sprint 完成研究服务接入。

联合验收：在隔离 Notes 服务已配置、无模型连接的条件下，普通模式从任务首页填标题/原文并启动，提交后直达记录，刷新可找回回执；导航和模式切换不丢输入。集成验收角色检查 UX01 的确定性子场景、UX07，以及 A09/A12/A14；研究场景与真实用户验收仍由 S2/S6 完成。

### sd-ux-contracts — 任务展示与业务投影约定

- 来源/责任：P01/P02/P03/P06；后端负责人，前端与插件负责人协作；交付给全部界面任务。
- 范围与产物：核对四个示例的业务标题、字段、默认值、保存位置、必要连接和结果类型；确定任务展示资料与原 package/workflow/revision 的关联、普通表单可用性判定、安全准备摘要、结果关联与有效设置变化的最小契约。确定现有字段复用及确需新增的持久化/API边界，留下具体示例和失败响应。
- 前置/就绪：当前源码和已接受方案足够开始。业务名称可按方案使用中文；展示元数据归属、普通服务预设、绑定变化核对方式待本任务验证，不擅自新增宽松 YAML 扩展字段或第二套执行定义。
- 完成/验证：逐一映射四场景和未知任务；没有完整表单的任务明确归专家，不能启动后突然要求 JSON。默认风险分析开启；账户、范围、保存位置可见；默认绑定有作者或用户选择依据。通过现有定义/launch 合同核对与样本评审，必要 API 改动必须有安全投影测试。交付可供 S1 表单、S2 连接/结果和 S3 持久化实现直接采用的接口样例。

### sd-ux-shell — 两入口导航、模式和统一视觉

- 来源/责任：P01/P05，UX07；前端负责人，产品验收角色协作。
- 范围与产物：任务/结果主导航、底部设置、专家开关和显示/时区偏好；Dashboard 内容并入任务首页，自动执行为任务内独立标签。同步 routes/layout、semantic tokens 和 DESIGN.md 为紧凑企业后台风格，复用 shadcn/Radix；灰白画布、细分隔线、约 14px 正文、统一约 4–6px 圆角、表格优先。
- 前置/就绪：视觉整理可立即开始；模式与任务路由接线需 `sd-ux-contracts` 的对象及草稿约定。只改变显示与入口，不借模式切换改变预算、授权或执行配置。
- 完成/验证：首次默认普通模式，专家入口可发现；刷新保留显示偏好，现有技术详情深链接可达且有明确上下文；切换不清空草稿。375/768/1024/1440px、键盘与焦点检查通过，现有 shell/route 组件测试及 `e2e/shell.spec.ts` 覆盖导航。交给所有后续页面统一使用；设置中的服务功能待 S2 接入。

### sd-ux-task-form — 业务任务目录与共享输入表单

- 来源/责任：P02，UX01/UX07；前端负责人，后端与示例维护角色协作。
- 范围与产物：按用途列出四场景，显示一句话说明、准备信息、最近使用；一次选中具体 workflow。实现中文标签/示例/行内错误、必填一页、更多选项、有效设置摘要；覆盖首批 schema，保留原始 scalar/array/null/object 值与缺失值语义。相同表单能力供计划与输入复用使用。
- 前置/就绪：依赖 `sd-ux-contracts` 的字段与资格约定，壳层集成需 `sd-ux-shell`；已知示例表单可先独立开发。S1 准备信息只显示当前可证实配置，其他显示未核实，实际启动仍校验；完整缺失连接摘要由 S2 `sd-ux-readiness` 接入，不倒置 S1/S2 前置顺序。
- 完成/验证：四场景普通输入均无 Schema/JSON/Apply 决策；无需先命名或保存配置即可执行。开启/关闭风险分析的实际设置与缺失提示一致；不支持的任务保持专家可达。表单边界、schema变化和切换草稿测试通过；修改示例时同步机器合同。交付给 S2 启动、S3 复用、S4 定时表单。

### sd-ux-capture — 保存原文到本次回执

- 来源/责任：P02/P03，UX01 子场景、UX03/UX05；前端负责人，Notes/后端负责人协作。
- 范围与产物：将普通表单接入现有稳定 launch 身份，开始即校验并提交，立即进入结果记录；最小结果页显示真实等待/执行/失败/完成状态和 Notes 保存回执、位置及取消入口。
- 前置/就绪：依赖 `sd-ux-task-form` 的 capture 表单和 `sd-ux-shell` 结果路由；集成需要隔离 Notes 发布/资源及执行服务已配置。无需模型服务；缺连接的修复在 S2，本任务显示明确阻塞原因。
- 完成/验证：受控 Notes 实际产生不可变笔记，刷新和重开页面可找回；响应丢失重试沿用身份且不多写；请求取消不提前显示已停止。用已有启动/取消合同与新增普通路径 E2E 收集关联 Run/笔记回执；仅 S1 子集完成，不能替代通用结果和研究验收。

## S2 — 四场景可用、就地连接与可信结果

顺序：连接契约 `sd-ux-readiness` 与结果契约 `sd-ux-result-contract` 可在 S1 约定可用后独立开始；连接 UI 接前者，结果 UI 接后者与 Finance 具体入口。所有四场景最终集成需要两路输出。容量以先完成一条研究链、再覆盖另外两项及错误路径为假设。

联合验收：本地实际插件进程、Temporal 与受控模型/provider 下，四场景均有真实运行/产物；研究首次缺连接能就地修复，结果显示来源、时间、缺失及保存未知状态。检查 UX01/UX02/UX03/UX05 和 A02/A08/A09/A13/A14/A15。受控研究结果不证明真实供应商可用。

### sd-ux-readiness — 安全准备信息与绑定核对

- 来源/责任：P02/P03，UX02/UX05；后端负责人，插件负责人协作；接收方为连接、启动和重跑界面。
- 范围与产物：复用 launch 解析规则，提供缺少的具体服务/资源、配置存在性、有效账户/范围/保存位置和修复入口所需安全投影；按 S1 约定提供再次运行前的关键绑定变化核对。区分配置就绪、未观测、失败，不把插件 enabled 或 hasCredentials 宣称在线。
- 前置/就绪：依赖 `sd-ux-contracts` 安全摘要与核对契约；可开始后端实现，不需等待连接 UI。实际服务健康验证如需探测，必须定义无业务写入的方法及其权限条件。
- 完成/验证：禁用坏插件不阻断无关任务/历史；读取不调度、不初始化无关插件、不返回 secret。核对后至真正启动间若绑定变化，不能静默绕过应展示的业务变化；启动仍是最终授权校验。聚焦 launch、安全投影、绑定变化与并发更新测试通过，提供可消费的成功/缺失/失效样例。

### sd-ux-connections — 就地连接与已连接服务设置

- 来源/责任：P02/P05，UX02/UX07；前端负责人，后端与部署配置角色协作。
- 范围与产物：在任务中补齐已验证服务预设所需字段及凭据；提供“已连接服务”管理、状态和使用范围。普通路径不输入资源 ID/凭据 JSON；自定义 endpoint、协议、模型 ID及高级参数归专家。保存位置和业务范围仍显式确认。

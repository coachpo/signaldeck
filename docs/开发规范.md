## 工作流解耦规则

产品原则见[工作流与平台解耦原则](产品说明.md#工作流与平台解耦原则)；Workflow 展示和插件结果链接的线格式分别由[工作流解耦方案](工作流解耦方案.md)和[插件接入](writing-extensions.md#声明结果页面链接)维护。

- 包和 Workflow key 只用于定位记录、引用、授权和来源追溯，不作为选择业务表单、默认值、执行器或结果解释的分支条件。字段名、资源 ID、插件 ID 和输出形状也不能充当隐含的业务类型注册表；测试可以使用自己的业务标识，但不能据此给生产代码建立白名单。
- 新增声明能力（默认值、控件提示、结果展示、预算字段等）时，先定义带版本的闭合契约，再同步修改 parser、schema 校验、compiler/hash、API 类型、编辑器、导入/导出、测试和该能力的唯一权威文档。不支持的关键字继续拒绝，不用任意字典、代码表达式、静默丢弃或只在前端接受来绕过服务端协议。缺省的新字段不写入 canonical 序列化，旧定义的 hash 和 digest 保持不变。默认值的应用时机必须明确，校验、重跑和读取历史时不改写已提交的输入。
- 解耦改动用独立维护的最小 fixture、全新包名和改名字段验证通用性；只删掉某个硬编码字符串不算完成证据。可观察的验收合同见[解耦验收](产品说明.md#解耦验收)。

### 预算与模型输出上限

- `maxTokens`（每次 Agent 执行的累计 token 额度）接受正整数或 `unlimited`；可选的 `maxOutputTokens`（单次输出上限）接受正整数、`auto` 或 `provider_default`。显式 `null` 和非正数一律拒绝，不能冒充省略或不限额。
- 省略 `maxOutputTokens` 时按 `auto` 执行。`auto` 在累计额度有限时使用剩余额度，不限时不发送输出上限；数值在累计额度有限时取它与剩余额度中较小的一个；`provider_default` 从不发送输出上限参数，也不发送 `null`。
- 模型资源的可选 `providerCapabilities` 是闭合对象，必填的 `outputTokenLimitParameter` 取 `max_tokens`、`max_completion_tokens` 或 `max_output_tokens`：前两者只用于 `apiStyle: chat_completions`，后者只用于 `responses`，组合不匹配时拒绝。省略时 Chat Completions 使用 `max_completion_tokens`，Responses 使用 `max_output_tokens`；显式 `null` 拒绝。该配置随模型绑定冻结，由 I/O adapter 选择实际 HTTP 字段，不按 endpoint 或模型名推断，读取时也不探测服务。部分 OpenAI 兼容网关忽略 `max_completion_tokens` 而遵守 `max_tokens`，超出上限的输出会以 `model_output_limit_exceeded` 失败；这类服务应配置为 `max_tokens`。

## 外部合同与凭据

- 对外 JSON 使用 camelCase，内部 Python 使用 snake_case；请求和响应 schema 继承 `backend/app/schemas/common.py` 的 `CamelModel`，不在路由里手写转换。`CamelModel` 设 `extra="forbid"`，请求中的未知字段按请求校验失败处理。
- `backend/app/main.py` 把应用错误（`ApplicationError`、`ApiError`、Core 制品不可用、定义与配置校验）、请求校验错误（422 `validation_error`）和框架 HTTP 错误统一映射为 `{code, message, details[]}`：未匹配的路由为 404 `route_not_found`，不允许的方法为 405 `method_not_allowed`（保留 `Allow` 头），其他为 `http_error`。新增的错误详情必须经过 `backend/app/core/errors.py` 的现有安全过滤，并且不得包含 API key、password、token、secret、authorization、内部堆栈、数据库凭据或个人数据。
- 金额、数量和市值跨 API 边界以十进制字符串传输，不用浮点数；时间以 UTC ISO 8601 字符串传输并以 `Z` 结尾（`CamelModel` 分别序列化 `Decimal` 和 `datetime`）。
- 资源凭据只写：通过写入表单提交，加密保存并带 revision；读取只返回是否存在和 revision，不回填到表单，也不出现在错误详情、日志或下载内容中。Run 冻结 credential revision，只有 I/O adapter 按该 revision 解析凭据；revision 已轮换时明确失败，不改读当前版本。凭据值不得进入模型消息、工具参数、定义、快照、引擎 payload、日志、诊断或产物。

## Frontend 规则

- 业务草稿只放在应用内存，刷新或关闭前由 `beforeunload` 提醒；需要跨刷新保留时使用服务器任务草稿接口。浏览器存储不保存业务输入、准备配置或凭据：`localStorage` 只存主题、专家显示开关和新安排的默认时区，`sessionStorage` 只存插件页面返回主站所需的平台地址，以及未确认重跑的 `launchId`、包/工作流身份和核对令牌。
- 新增模块级的保留草稿或未确认命令身份时，必须调用 `frontend/src/lib/retained-work.ts` 的 `registerRetainedWork`。页面文件因重启或重新部署无法加载时，`chunk-recovery.ts` 只在没有登记内容时自动重新加载；存在登记内容，或重新加载后首次打开仍失败时，保留路由错误页。
- 经 HTTP 以非本机地址打开的页面（局域网地址或可信反向代理）不是安全上下文，浏览器不提供 `crypto.randomUUID`、`crypto.subtle` 和 `navigator.clipboard`；`localhost` 和 `127.0.0.1` 属于安全上下文，本机检查发现不了这类问题。随机标识使用 `frontend/src/lib/random-uuid.ts`；剪贴板写入使用 `frontend/src/lib/clipboard.ts` 的 `copyText`（插件页面通过 `window.SignalDeckUI.copyText` 调用），它在缺少 `navigator.clipboard` 时改用浏览器复制命令，只在同一次点击处理中有效，因此调用前不能先等待其他异步操作。ESLint 禁止 `frontend/src` 直接访问 `randomUUID` 和 `navigator.clipboard`。其他只在安全上下文可用的能力必须先检测可用性或捕获失败并提供替代路径，不能让页面渲染失败。单元测试用 `frontend/src/test/insecure-context.ts` 的 `stubInsecureContext()` 去掉 `crypto.randomUUID` 和 `crypto.subtle`，`frontend/src/routes.test.tsx` 在安全和非安全两种上下文下渲染全部路由。

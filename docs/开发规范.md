## Backend 规则

- 外部 API JSON 使用 camelCase，内部 Python 使用 snake_case；请求/响应 schema 通过 `CamelModel` 和现有 alias 机制实现，不在路由中手工复制转换规则。
- `ApiError` 和请求校验错误使用 `{code, message, details[]}`；可选 token middleware 的 401 当前返回 `{detail: "Unauthorized"}`，不要将全部 HTTP 错误都视为同一 schema。新增 API-owned 错误详情必须经过现有安全过滤，不得包含 API key、password、token、secret、authorization、内部堆栈、数据库凭据或个人数据。
- Money、quantity 和 market value 跨 API 边界使用字符串；不要用浮点数表达需要精确传输的金额。
- 数据库使用 SQLAlchemy model/repository/service 分层。schema 变更按当前 `create_all` 约定处理；没有迁移框架时，不伪造 Alembic 迁移兼容路径。
- 新 API router 只负责边界校验、授权依赖、调用 service 和响应投影；业务编排、队列、provider 调用和事务责任留在对应 service/repository。
- Workflow Package parser 负责 YAML source safety、闭合字段和 graph semantic validation；compiler 负责确定性排序和 canonical hash。编译产物可包含运行所需的私有 MCP 配置，不能直接当作公开响应；读取和导出通过对应安全投影。package schema 默认 closed，不加入 `additionalProperties`、`allowAdditionalProperties` 或 `patternProperties`。
- package source、export、run provenance、日志、诊断和读取接口不得泄露 secret-bearing MCP `env`、`headers`、`query`、raw API key 或 package secret。运行来源和导出保持现有安全投影；不要把内部 snapshot 行标识加入公开契约，现有资源 id 仍按 API schema 使用。
- 扩展必须通过 `Extension` 和 `INSTALLED_EXTENSIONS` 静态注册；不得引入动态发现、运行时安装、隐式 registrar side effect 或 marketplace surface。tool key 必须保持 owner-qualified。
- 修改 demo Workflow Package YAML 时同步检查 parser/compiler/preflight 测试和锁定 hash；demo 文件是产品契约，不是随意的示例数据。
- FastAPI `<0.137` 的依赖封顶暂不解除；只有 Logfire/OpenTelemetry 解锁条件满足并重新验证 405/partial-route-match 场景后才可调整。

## Frontend 规则

- 页面和 feature folder 拥有 route params、domain copy、hooks、mutation、toast、navigation 和 validation；`components/ui` 和 shared components 保持 presentational，不放 API 或领域编排。
- 所有 TanStack Query key 使用 `frontend/src/lib/query-keys.ts` 的 canonical registry；mutation 必须 invalidate 受影响的 list、detail 和 related scope。
- `/api/v1` extension surface 使用 `request`；平台 `/api` 使用 `requestPlatform`；浏览器类型镜像外部 camelCase contract。
- secret-like 值通过写入表单提交，操作者新输入的草稿可以暂存于表单状态；已保存值的读取只能显示安全 presence，不得从读取接口回填或在错误详情、日志和下载内容中暴露原始 secret。
- 遵守 `frontend/DESIGN.md` 的 semantic token、shared shell、status、table、dialog 和响应式规则；不新增 route-local theme、UI library 或装饰性视觉系统。
- `react-hooks/set-state-in-effect` 保持 recommended severity，不通过局部 ESLint downgrade 规避问题。

## 依赖与镜像规则

- 依赖清单、锁文件、CI 和 Docker 运行时的版本差异见 [`CONTRIBUTING.md`](../CONTRIBUTING.md#开发环境与依赖)；不要将 CI 与镜像已验证的版本范围混为一谈。
- Node 26 镜像通过 `npm install -g pnpm@10.30.1` 安装 pnpm；不得重新引入 `corepack enable`。
- 根 Dockerfile 和根 Compose 只属于 local/demo；CI 的 `docker-images.yml` 只构建 `backend/Dockerfile` 和 `frontend/Dockerfile`。改动根镜像时必须额外运行本地 `docker build .`。

## 评审要求

评审至少确认：变更没有跨越 [`架构说明.md`](架构说明.md) 的依赖方向；没有复制或削弱 secret/data-integrity 边界；没有重新引入已移除产品面或兼容 shim；涉及 package artifact、运行快照、schedule provenance、API error contract、扩展注册或前端 query invalidation 时，相关测试和文档已同步。

适用的格式、lint、类型、单元测试、E2E、build 和 `git diff --check` 命令统一记录在 [`CONTRIBUTING.md`](../CONTRIBUTING.md)，本文件不重复命令清单。

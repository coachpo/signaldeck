## 权威边界

共享设计原则、实现原则、完成定义、开发环境、检查命令和当前开发策略以 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 为准。本文件只维护 SignalDeck 特有的技术与实现规则；组件职责和依赖方向以 [`架构说明.md`](架构说明.md) 为准。

当前采用 v2 Workflow Package、Temporal 单一执行引擎和进程外插件。需求、范围与验收以 [`产品说明.md`](产品说明.md) 为准，数据、兼容政策及完成历史以 [`STATUS.md`](../STATUS.md) 为准；已移除的静态扩展、步骤执行器及旧 API/schema 不是兼容约束。

## 工作流解耦规则

遵循[产品解耦原则](产品说明.md#工作流与平台解耦原则)；实现边界及历史展示差异由[架构说明](架构说明.md#工作流边界与已知偏差)维护。下列规则适用于 Core 后端、前端、执行入口及预置数据工具。

- 包/Workflow key 只用于定位记录、引用、授权和来源追溯，不得作为选择业务表单、默认值、执行器或结果解释器的分支条件。字段名、资源 ID、插件 ID、输出形状也不得充当隐含的业务类型注册表。示例和测试可以包含业务标识，但不能据此为生产代码建立白名单。
- 目录来自保存的包记录；校验和输入来自所选修订的 schema，业务文案及展示选择来自公开声明。优先复用已有 schema/value 编解码和通用组件；只按受支持的契约能力选择控件或完整 JSON 编辑，不按某个场景的字段集合判断支持度。
- 新增默认值、控件提示或结果展示能力时，定义有明确字段和版本的闭合契约，同步 parser、schema 校验、compiler/hash、API 类型、编辑器和导入/导出。当前不支持的关键字仍须拒绝；不得用任意字典、代码表达式、静默丢弃或前端单方面接受来绕过服务端协议。默认值的应用时机须明确，不能在校验、重跑或读取历史时偷偷改写已提交输入。
- 结果投影只解释明确的通用展示声明和已确认执行事实；业务限制由工作流/插件产生，不能检查业务输入后代写结论。保留 Run 状态、内容可用性和外部效果 unknown 的区别；可选分支 skipped 不直接决定业务完整性。历史读取使用冻结声明，缺少展示信息时保留通用值、产物和证据，不读取当前工作流补写历史解释。
- 插件拥有业务记录类型、路由及页面；Core 只消费经验证的通用链接/产物声明，不硬编码报告或笔记 URL 参数。服务名称及业务 scope 标签来自资源、插件发布或部署声明，未知项按通用方式展示；平台自己的状态、预算和协议术语仍可由平台定义。
- 预置定义应作为独立 YAML/数据包交付，通用导入共享普通定义的解析、编译、规范化与修订语义。保留“仅安装缺失项”的原子保护；导入器不能使用会推进同名包指针的普通保存操作冒充安全初始化。工作流数据不得嵌入 Core 源码或通过换文件扩展名继续进入其可执行清单。
- 解耦变更须用不在 demo 名单内的工作流和重命名后的业务字段验证通用性，同时保留现有四场景及不可变快照回归。具体可观察合同见[解耦验收](产品说明.md#解耦验收)；不能仅以删除某个硬编码字符串作为完成证据。

当前版本约定：Budget 可选 `maxOutputTokens` 为正整数，显式 null 拒绝，省略不进入 canonical 序列化，运行映射不能超过它或剩余总预算；包根保持 v2；schema 节点用 `x-signaldeck-schema: signaldeck.schema/2` 显式启用 default/examples，不向子节点继承；Workflow presentation/1 与工具 resultLink/1 使用闭合声明。省略的新字段不能进入旧 canonical hash，显式 null 不冒充省略。结果选择只依赖冻结 schema/确认输出，链接在 Launch 的实际发布绑定时验证。Workflow 展示线格式由[工作流解耦方案](工作流解耦方案.md)维护，插件 resultLinks 发布合同由[插件接入](writing-extensions.md#声明结果页面链接)维护。

## Backend 规则

- 外部 API JSON 使用 camelCase，内部 Python 使用 snake_case；请求/响应 schema 通过 `CamelModel` 和现有 alias 机制实现，不在路由中手工复制转换规则。
- `ApiError` 和请求校验错误使用 `{code, message, details[]}`；可选 token middleware 的 401 当前返回 `{detail: "Unauthorized"}`，不要将全部 HTTP 错误都视为同一 schema。新增 API-owned 错误详情必须经过现有安全过滤，不得包含 API key、password、token、secret、authorization、内部堆栈、数据库凭据或个人数据。
- Money、quantity 和 market value 跨 API 边界使用字符串；不要用浮点数表达需要精确传输的金额。
- Core 领域与应用层通过值对象和小型 Protocol 接口交互；SQLAlchemy 与 Session 限于 infrastructure/组合根。插件拥有独立 metadata、数据库和角色，不交换 ORM、Session 或万能 Context。schema 变更按当前 `create_all` 约定和数据政策处理；不伪造迁移兼容路径。
- Agent 的业务差异通过定义、模型配置、工具集合和策略组合表达，不建立业务 Agent 继承链或万能 BasePlugin。ToolCatalog 只承担冻结契约、别名和分发；不扩展为可任意取得服务的全局容器。
- API router 负责边界校验、依赖组合、应用调用和响应投影。启动事务原子保存 Run、resolved spec 和 command；Temporal 是唯一生命周期与 DAG 调度权威，dispatcher 只投递命令，读取投影不能发起调度或执行重试。
- 普通任务的准备摘要与 `bindingToken` 必须使用同一次捕获的资源/插件配置；准备检查不探测外部服务，`ready` 不等于在线或已验证可用。启动核对包修订、工作流、输入及模型/资源/插件绑定；绑定变化返回明确冲突，由操作者重新核对。已有 `launchId` 先恢复持久化命令，再处理可变配置；同身份不同意图仍须拒绝。
- 常用配置保存包修订并按当前闭合输入 schema 校验，凭据仍属于资源连接。保留对象、数组、标量和显式 `null` 的 JSON 语义，以 `hasParameters` 区分保存输入与仅收藏；包变化须显式标记复核，删除常用配置不影响已有 Run 或计划。
- 定时执行使用 Temporal Schedules，明确时区、重叠和 catchup 策略；Schedule action 必须覆盖关联 Run 的实际生命周期，不能在 Launch 或 start command 返回时提前完成。重新投递保持原触发身份，新触发创建独立 Run 并保存来源。
- 计划预览使用 Temporal 返回的时间，区分草稿与已同步版本；不能用浏览器猜测的 cron/DST 时间冒充执行服务结果。创建计划的 `requestId` 重试先恢复已保存身份并校验请求一致性，不能因包的后来变化阻断原命令回执。
- Workflow Package parser 负责 YAML source safety 与源码诊断；compiler 合并控制/输入/条件依赖、校验引用和映射类型，生成确定性排序与 canonical hash。UI/YAML 共享同一定义；Agent 不拥有节点依赖。schema 使用固定闭合子集，不加入 `additionalProperties`、`allowAdditionalProperties` 或 `patternProperties`，不静默丢弃未支持约束。
- 映射和条件只使用既有声明式语法，不引入任意代码或网络表达式；缺失输出必须显式处理。独立就绪节点不能被无关慢分支或整层屏障阻塞；节点并发、Agent 工具并发和外部资源限流分别保持其配置语义。
- 资源凭据仅由 I/O adapter 解析固定 revision；模型消息、工具参数、定义、快照、引擎 payload、日志、诊断、读取及产物中不得包含凭据值。配置使用非敏感 scope，读取仅投影 presence/revision；凭据版本不可用必须明确失败，不能静默读取当前新版本。
- 插件以独立制品和进程接入，保持 `publisher/plugin/tool` 身份和冻结 release/contract digest。单一工具契约派生目录、模型声明和 dispatch；Core 不导入业务插件。Finance 拥有 Templates/Reports。实现规则见 [`writing-extensions.md`](writing-extensions.md)，插件市场仍不在范围。
- 成功输出不可覆盖；恢复复用同 Run 已确认调用，写效果 unknown 先按原 operationId 查询/去重。同 operation 的核实、执行与确认须持有独占所有权，重叠投递等待已有操作而不增加业务写入或提前使 Agent 失败。旧效果未核实时，本次重投被拒绝也不能证明旧效果未发生。跨 Run 读缓存必须显式配置并保留来源/新鲜度。
- 节点、Agent、逻辑调用和网络尝试保留不同身份，重试不延长首次 deadline。向 Temporal Activity/Child Workflow 转发取消使用单次转发、等待实际结束的路径；重复取消不得重复发出同一引擎取消命令。本地 timeout 到期与操作者取消分开分类，取消接受不等于实际停止或撤销效果。
- 已完成 Agent/节点的终态投影在取消到来时完成短持久提交后再传播取消，不启动新的业务 I/O。不能依赖只扫描未终结 Run 的补投影来修复已终结 Run 遗留的 running 证据；初始 running 投影保持可取消。
- MCP 取消通知使用匹配活动 tools/call 的 requestId、协议和会话身份；发送必须有界，通知失败不改变原取消语义，也不能证明写效果未发生。插件应尽力停止关联工作，无法确认的效果继续保留 unknown。
- 执行 OTel span 只记录允许的静态身份属性，不记录输入输出、凭据、异常文本/堆栈、动态事件或 status description。跨 Temporal/MCP 只传播 traceparent，不允许资源 headers 覆盖追踪或 MCP 协议字段。外部 exporter 和重放产生的追踪标记不得成为执行或历史读取的正确性依赖。
- 大值和引擎 payload 使用不可变内容寻址引用；读取验证 digest/size，业务 schema 不得占用内部 `$artifact` envelope。固定 Core/插件制品缺失或不匹配必须失败，不回退至当前代码。
- 修改 demo Workflow Package YAML 时同步检查 parser/compiler/launch 测试、外部导入行为与 `demo/contracts.json` 锁定 hash；demo 文件是产品契约，不是随意的示例数据。
- FastAPI `<0.137` 的依赖封顶暂不解除；只有 Logfire/OpenTelemetry 解锁条件满足并重新验证 405/partial-route-match 场景后才可调整。

## Frontend 规则

- 页面和 feature folder 拥有 route params、domain copy、hooks、mutation、toast、navigation 和 validation；`components/ui` 和 shared components 保持 presentational，不放 API 或领域编排。
- 普通任务、结果、设置与专家工作区使用同一套定义和命令；显示模式只改变呈现，不触发业务写入。切换模式保留未保存草稿和复杂值；普通表单不支持的合法 schema 在当前模式提供完整 JSON 编辑，不能隐藏任务、删字段或套用默认值改变原输入。
- 所有 TanStack Query key 使用 `frontend/src/lib/query-keys.ts` 的 canonical registry；mutation 必须 invalidate 受影响的 list、detail 和 related scope。
- 自动准备查询属于 Workflow Package 分组，就地连接保存后重新获取准备摘要。未确认的启动、重跑和计划创建保留原命令身份及其输入；访问证据后返回未确认重跑，仍重试同一 `launchId`。出现 unknown 写效果时，重新执行前保留明确核实步骤。
- 结果正文、回执、附件、缺失及 unknown 来自服务端结果投影，不能将取消接受当作写效果撤销。历史搜索、过滤、排序和分页使用服务端全库查询，保留 URL 查询与创建时间上界，不以当前加载页冒充全部历史。
- Core 平台 `/api` 使用 `requestPlatform`；独立业务页面和 API 属于插件，不能把旧 `/api/v1` 路径当作 Core 扩展入口。浏览器类型镜像外部 camelCase contract，运行图/边来源消费服务端编译结果。
- secret-like 值通过写入表单提交，操作者新输入的草稿可以暂存于表单状态；已保存值的读取只能显示安全 presence，不得从读取接口回填或在错误详情、日志和下载内容中暴露原始 secret。
- 遵守 `frontend/DESIGN.md` 的 semantic token、shared shell、status、table、dialog 和响应式规则；不新增 route-local theme、UI library 或装饰性视觉系统。
- `react-hooks/set-state-in-effect` 保持 recommended severity，不通过局部 ESLint downgrade 规避问题。

## 依赖与镜像规则

- 依赖清单、锁文件、CI 和 Docker 运行时的版本差异见 [`CONTRIBUTING.md`](../CONTRIBUTING.md#开发环境与依赖)；不要将 CI 与镜像已验证的版本范围混为一谈。
- Node 26 镜像通过 `npm install -g pnpm@10.30.1` 安装 pnpm；不得重新引入 `corepack enable`。
- 根 Dockerfile 和根 Compose 只属于 local/demo；CI 的 `docker-images.yml` 只构建 `backend/Dockerfile` 和 `frontend/Dockerfile`。改动根镜像时必须额外运行本地 `docker build .`。

## 评审要求

评审至少确认：变更遵循 [`架构说明.md`](架构说明.md) 的依赖方向及 [`产品说明.md`](产品说明.md) 的范围和验收；没有复制或削弱 secret/data-integrity 边界；没有重新引入范围以外的已移除产品面或兼容 shim；涉及 package artifact、运行快照、schedule provenance、API error contract、插件发布或前端 query invalidation 时，相关测试和权威文档已同步。

适用的格式、lint、类型、单元测试、E2E、build 和 `git diff --check` 命令统一记录在 [`CONTRIBUTING.md`](../CONTRIBUTING.md)，本文件不重复命令清单。

# Docs Guide

Use the [document index](README.md) to choose the single authority for each fact. Canonical product and engineering documents retain their existing Chinese paths; agent guides and existing specialist documents retain their established language.

- Document implemented behavior and verified commands in current product/architecture references. Keep accepted future design and target acceptance in [the iteration target](迭代目标.md), with frozen baseline identity owned by [STATUS.md](../STATUS.md#冻结迭代目标). Keep current scope and deployment claims grounded in source, configuration, and tests; target acceptance does not prove implementation.
- Update the affected authority first, then its linked summaries. Refresh [the project entry](../README.md) and [the document index](README.md) when the durable document map changes. Use relative links to sibling documents and repository evidence.
- Keep current persistence details in [data-model.md](data-model.md), installed static-extension contracts in [writing-extensions.md](writing-extensions.md), and dependency unlock conditions and validation commands in [handover-deps-follow-up.md](handover-deps-follow-up.md). Future plugin boundaries belong to the iteration target. Do not duplicate these contracts in product or agent-guide inventories.
- Preserve managed marker regions and update them through their owning documentation skill. The development tier is selected in `STATUS.md`; the corresponding strategy belongs to `CONTRIBUTING.md`.
- Do not create a second canonical path or an unselected bilingual counterpart without an explicit language migration. Link canonical rules instead of copying them into specialist documents.
- Examples and command descriptions must preserve secret redaction and the local/demo boundary of the root combined image. Do not imply that credentials are readable product data or that development defaults establish production readiness.

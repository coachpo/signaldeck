# 产品说明

SignalDeck 是供可信单用户使用的个人 Agent 工作流平台。普通操作从选择任务、填写业务信息开始，执行后阅读结果并可安排重复执行；专家通过助手、步骤、条件、资料来源、服务和预算控件制作可复用工作流，并检查执行过程。

本文是当前产品范围、行为和验收合同的权威。使用对象、部署和数据政策见 [`STATUS.md`](../STATUS.md)，技术边界见[架构说明](架构说明.md)。

## 产品范围

普通模式的导航为**任务、结果、执行更新、设置**。任务页列出全部已保存的 Workflow，并提供已保存草稿、常用配置和自动执行入口；结果页提供历史查询和正文阅读；执行更新汇总需要查看的运行变化；设置管理显示偏好、新安排的默认时区和已连接服务。新实例默认没有工作流，用户通过专家制作或显式导入添加任务。专家模式增加工作流制作、服务连接和扩展服务入口；普通/专家只是展示偏好，不划分权限，不改变执行能力或已有配置。Temporal 界面只随本地运行栈在本机开放，供运维排查，不属于产品界面，正式部署不提供它。

业务能力由独立插件提供：Finance 拥有格式、报告（Templates/Reports）和金融市场数据，并提供报告工作区；Notes 拥有不可变笔记和只读资料工作区；Digital Oracle 只提供研究数据工具，没有页面或业务存储。各插件的能力、页面与 API 见[插件说明](../plugins/README.md)。部署方登记的可信插件可声明页面入口，显示在侧栏的“应用”分组并在主站内打开；插件页面无法打开时提供重试和返回，主站任务、已有结果和设置继续可用。宿主行为与协议见[统一插件页面](writing-extensions.md#统一插件页面)。

所有显示模式及独立插件页面均使用业务语言表达操作、状态和恢复方式。页面、表单、弹窗、提示、错误、空状态、加载状态和结果详情不得展示平台内部 ID、原始 API 响应、堆栈、存储路径、schema、调度引擎或资源绑定等实现信息；折叠区和专家模式也不例外。受支持的操作必须通过适当控件完成，不能要求用户编写 JSON、YAML 或 cron，不能只重命名术语、补长篇解释或删减能力。工作流文件以现有格式导入和导出，用户无需阅读或编写源码。用户自己的正文、代码和原始业务附件按原文保留；其内容不作为平台技术展示的过滤对象。

工作流定义根始终是 Workflow Package，包内包含 `agents` 和 `workflows`，线格式见[设计定案](工作流解耦方案.md#设计定案)。不提供认证/RBAC 产品面、多租户、插件市场、Studio、Tryout、memory、fork、portfolio、simulation 或 backtest。

## 工作流与平台解耦原则

SignalDeck 的产品定位是通用工作流执行平台。所有工作流，无论导入还是自行制作、手动还是定时执行，都是遵循公开契约的数据定义；平台与具体工作流不得互相依赖其实现。任务发现、输入、结果和数据分发均按下列原则实现；历史展示差异及大产物选择限制见[架构边界](架构说明.md#工作流边界与已知偏差)。

- 平台负责通用的定义管理、校验、编译、资源绑定、执行、调度、证据存储和呈现。任务发现、输入编辑及结果阅读都必须适用于符合契约的任意工作流，不能依赖具体包、Workflow、插件的预置名单或业务字段名称。
- 工作流的业务输入、默认值、提示词、DAG、业务条件及展示声明属于包数据；外部业务操作、数据和专用页面属于独立插件。新增或更新使用现有平台能力的工作流，只需交付定义及所需插件/资源配置，不应修改或重新发布 Core 或前端。
- 工作流可以引用公开且版本明确的包、schema、工具、资源及展示契约；这种契约依赖不等于实现耦合。工作流及其业务实现不得导入 Core 私有模块、访问 Core 私有表、调用特定 Worker 内部函数，或依赖内置任务页面才能执行。
- `demo/` 仅保存示例工作流，不是平台组件。除说明性文档外，平台源码、测试、构建、启动、分发和验证脚本不得依赖或引用该目录及其内容，包括具体文件、包标识、业务声明和派生合同；修改、移动或删除示例不要求修改平台实现或测试。平台及插件测试使用独立维护的最小 fixture，不从示例读取、生成或同步，也不固定示例场景、示例 hash 或示例文件数量。

新的通用能力可能需要演进平台契约；演进须面向同类工作流的共同需求，不能为某个工作流增加专用入口。可观察合同见[解耦验收](#解耦验收)，实现约束见[开发规范](开发规范.md#工作流解耦规则)，线格式与设计取舍见[工作流解耦方案](工作流解耦方案.md)。

## 任务与常用配置

任务首页枚举全部已保存的 Workflow，显示最近一次执行的时间、状态和结果入口；搜索匹配任务名称、说明和常用配置名称。任务名称、说明、字段标题和提示来自所选定义，不需要登记场景；Workflow 未填写名称时以其键显示。输入通过递归的字段、列表、文本、数值、开关、选项和空值控件编辑，不隐藏任务或静默丢弃字段，对象、数组、标量和显式 `null` 均保留。默认值只在新建值时填入（见[输入与标题](工作流解耦方案.md#输入与标题)），已有输入、常用配置、历史复用和已保存的计划参数都不补值；字段校验区分必填、可选、默认值和实际输入。

未保存的输入保留在当前应用会话内存中，离开后返回或切换模式可继续；刷新或关闭前提示保存，刷新后不恢复未保存内容。任务页可显式保存、继续和删除服务器草稿，包括尚未通过校验的输入；草稿保留原包修订、来源 Run 以及参数缺失与显式 `null` 的区别，定义变更时给出提示，启动仍使用原修订并重新校验，多窗口修改时提示冲突而不覆盖。尚未应用的原稿须由用户明确恢复，无法读取时可下载或明确放弃。用户可保存命名常用配置，也可只收藏任务而不保存输入；保存配置不执行任务、不启用计划，定义变化后保留原输入并要求重新核对，删除配置或取消收藏不影响包、计划、历史或结果。浏览器持久存储不保存业务输入或凭据。

业务输入通过基本校验后自动显示准备检查，列出缺少的连接、本次业务范围、保存位置、预算与授权；已就绪且没有待确认变化时可直接开始。准备检查只读取已保存的配置和已有调用记录，不探测外部服务：配置与最近调用观测分开显示，没有记录时说明尚未观测，历史成功不代表当前在线，模型观测只对应当前配置和凭据版本。缺少连接时可在本任务就地补齐：从部署方提供的服务预设中显式选择（不自动选第一项）、自行填写，或复制其他连接的非敏感设置，密钥单独填写且不会被复制，业务输入保持不变；插件服务未部署或未登记时仍需先完成部署或登记。准备之后连接或插件发布发生变化时，启动前要求重新核对。启动响应不确定时锁定本次输入，沿原启动身份核实或重试，不产生第二次执行。

## Workflow Packages

专家通过工作流、助手和步骤制作定义：新增与删除、工作说明、模型与工具选择、服务访问、字段规则、执行顺序、条件、资料来源、结果分节、预算及并发/重试限制均使用控件，复杂能力不以源码输入替代。删除仍被引用的对象前提示先调整相关内容，实际删除需确认。控件修改写入同一 YAML 文档，不形成另一套运行定义；切换页面或模式保留编辑中的内容，刷新或关闭前提醒保存。导入文件先经服务端检查，失败时保留当前草稿，通过后须确认才替换。保存时按规范化排版存储，因此保存后的导出保留全部设置与正文，但不保留文件注释和原排版。

流程图展示编译后的依赖关系，提供分层布局、缩放、平移和步骤定位，并标明执行顺序、资料来源和执行条件三类关联原因；它只供查看，不能通过拖拽改变调度。校验问题定位到相应工作流、助手、步骤或字段并说明修正方向，源码位置与编译诊断不直接呈现。

助手（Agent）以模型策略或确定性工具策略执行，可被不同步骤和 Workflow 复用，不能递归调用 Agent 或 Workflow；步骤通过 `uses` 引用助手，并拥有依赖、输入映射、条件、接受的上游状态和最大尝试次数。保存产生不可变的包修订，之后的编辑不改变已有 Run 的定义。启动时的问题以需要补齐的字段、连接或权限说明；定义通过校验不代表外部服务可用。工作流还可声明输入提示、运行标题和结果分节，闭合格式见[设计定案](工作流解耦方案.md#设计定案)。编译、冻结与复用的可观察合同见 A03、A04 和 A10。

## Resources 与 Plugins

Resources 管理 `model` 与 `tool` 两类资源：模型资源连接 OpenAI-compatible 的 `chat_completions` 或 `responses` 接口，工具资源指定所属插件、非敏感业务范围、并发上限和请求速率。Agent 只能使用被授权的资源；可用工具同时受已启用插件发布、Agent 的工具选择和本次 Run 的资源授权约束。服务以名称和用途展示，内部标识由平台维护。凭据单独填写，界面只显示是否已配置，编辑时不填写即保留原值；更新凭据后，仍需原凭据版本的未完成运行在调用该服务时明确失败，不会静默改用新凭据。存储规则见[数据模型](data-model.md#快照与凭据版本)。

插件管理通过安装文件登记已部署的服务，展示可用能力、启用状态、业务页面和已有调用产生的健康观测，不展示原始发布描述、工具 schema 或制品身份；列出插件不会连接或初始化插件，没有调用记录时如实说明。保存安装描述不会构建或启动服务，业务进程须另行部署。新运行使用所需且已启用的发布，历史运行保留原发布；插件可独立升级，仍被引用的旧发布须保留原制品和 endpoint。编写、配置与升级契约见 [`writing-extensions.md`](writing-extensions.md)。

## Runs

关闭浏览器不会停止已接受的运行。Run 状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`，节点与调用另区分 `blocked`、`skipped`、`timed_out`、`unknown` 等状态：条件为假产生跳过，不接受的上游终态产生阻断，缺失输出须按定义显式处理，Workflow 的失败策略决定继续独立分支还是整体停止。取消请求与实际终态分开显示，取消不撤销已发生的外部效果；写调用结果无法核实时保持可见的 `unknown`，不盲目重写；具有写工具授权的 Agent 不会整节点自动重启。并行、恢复、重试期限和冻结的完整合同见 A05–A11。

结果详情先显示已确认正文或保存确认，并列出来源、数据时间、执行时间、缺失内容、附件和实际运行状态；未取得数据时间时不以运行时间代替，未完成或失败节点的模型文本不提升为结果。分节由冻结的展示声明选择，正常跳过、业务告知或缺失、执行失败或取消以及未知效果分别显示；无声明的历史运行保留通用值、产物和执行证据，不按业务字段推测正文、标题或链接。正文、历史正文和文本附件按 Markdown 排版，原始业务 JSON 附件按字面值阅读，大产物可显式读取或下载。插件结果链接只来自冻结发布的声明；所属插件不可用时，Core 历史与已有通用产物仍可读取。

`unknown` 按本 Run 冻结的工具 effect 区分只读结果未确认与可能写入：只读失败不提示“可能已保存”，缺少可靠 effect 的历史证据按可能写入处理。失败或取消的运行保留已确认的局部产物；已确认的模型错误区分额度、认证、限流、模型不可用、输入、输出超限和未知原因并给出处理方向，缺少分类依据的历史错误不补推原因。执行过程按冻结的助手名称、步骤关系、实际状态、时间和尝试次数追溯工作，输入、工作要求、服务访问和执行限制以可读摘要呈现，不显示原始请求、响应或快照源码。

历史在服务端对业务标题、任务或运行标识及已保存输出做字面搜索，可按状态、任务、来源、日期、收藏和阅读状态筛选，按时间或标题排序并分页；可切换“进行中”和“需要处理”分组，后者包括失败运行和仍有未知逻辑调用的运行。日期按浏览器当地日历日换算。进入结果或执行过程后返回保留筛选与页码，刷新保留筛选、回到第一页并纳入新运行。

重跑创建新 Run：沿用原包修订、输入和有效预算并记录来源，重新解析当前资源、插件和 Core 制品，使用新的期限，不复制旧结果。重跑前以可读摘要展示原设置及本次服务或范围变化；原结果含可能写入的 `unknown` 时，须先确认已核实目标位置和执行过程。重跑响应不确定时，同一标签页刷新或返回后仍沿用原命令身份，业务输入从服务器重新读取。“修改输入后开始”按原包修订和 schema 校验修改后的输入，创建带来源的新运行，不改写原输入或结果。当前没有删除包或 Run 的入口。

结果页以字段标签和值呈现完整业务输入。复制和 Markdown 导出使用冻结的确认分节，附带运行状态、来源、时间和返回完整结果的链接；未声明展示时，完全相同的确认内容合并阅读并保留全部来源步骤，显式声明的不同分节不合并。附件须显式选入，未选内容和延后解析的分节会列明，未读取的所选附件不能作为完整内容导出；复制或下载失败保留选择供重试。

每次运行和浏览器当地日显示已报告的输入/输出 token、逻辑调用数、耗时以及用量缺失和网络尝试覆盖说明；同一逻辑调用的模型与网络证据不重复相加，缺值显示未知，不冒充零消耗、余额或供应商账单。当地日按逻辑调用首次开始的时间和明确的 IANA 时区归属，跨日重试不重复计入。

任务的“用量与时间限制”可统一或按助手设置累计模型用量、单次输出、模型处理次数、服务操作次数、最长执行时间和同时执行的操作数；累计用量可指定额度或不设限，单次输出可按剩余额度、指定额度或由模型服务决定，取消覆盖即沿用工作流默认。界面显示最终值和来源，专家制作用同一控件保存工作流默认值。预算按每次助手执行分别计算，同一助手用于多个步骤也不共享额度，助手时限仍受整个任务时限约束。由模型服务决定时不发送输出长度参数；累计额度在响应后核验，已发生的超额消耗无法撤回。取值格式见[开发规范](开发规范.md#预算与模型输出上限)。

供应商报告的输出超过实际请求上限、有限累计额度下缺少输入或输出计量、已发送单次输出上限但未报告输出计量，或服务明确报告截断时，该 Agent 明确失败，不继续调用，也不把响应当作成功结果；已发生的调用和已报告用量保留，其他分支按失败策略处理。预算耗尽不会通过自动重试扩额；平台预算、供应商账户额度、截断和超时分别说明。输出长度字段由模型资源的 provider 能力配置选择，见[预算与模型输出上限](开发规范.md#预算与模型输出上限)。

预算覆盖与输入一起保存在显式草稿、常用配置和重复安排中，启动响应不确定期间不能修改。结果页显示本次冻结的预算；重复安排每次触发按当时的工作流默认值解析并冻结已保存的覆盖，所选助手已删除或不再参与时明确失败。

结果可收藏、标为已读或未读并填写个人备注；这些标记独立于运行、快照和正文，多窗口修改冲突时须读取最新状态后再确认，备注草稿保留。标为已读同时确认当时的执行更新，之后的状态变化产生新的更新。“执行更新”列出已有运行当前的完成、失败、取消或待核实状态，以及没有生成 Run 的定时启动失败；重复读取不产生重复项或启动执行，已查看但写入效果未知的更新仍留在待处理视图，核实后的状态产生新的未读更新。它是当前事实列表，不是完整事件日志。

比较页固定两个 Run 及两侧选定的分节，可从服务端历史搜索分页中选择；两侧分别保留状态、原修订、输入、来源与时间，文本差异只说明原文不同，不生成业务结论。大产物须显式读取，过长的变更区按完整段落显示删除与新增，不静默截断或改写原输出。

## Scheduled Tasks

任务或结果页可发起“设置重复执行”，继承任务和输入，名称可修改，只有保存才创建安排。频率控件提供每天、每周、每月；组合日历可多选或按范围、间隔选择月份、日期、星期、小时、分钟、秒和年份，也可设置固定间隔及参考起点，不要求填写时间表达式。控件保存为 cron 与 IANA 时区：未修改的合法规则保持原值，无法解读的旧规则保留原安排并可通过控件明确重设，修改名称或输入不会覆盖它。新安排只在创建时采用设置中的默认时区，已保存的时区不随偏好或浏览器所在地改变。

“上一次尚未结束时”可选择跳过本次、保留一次等待上次结束或允许同时执行，“错过后多久内补做”至少 10 秒；修改频率不覆盖已有策略。日历、夏令时、重叠和补做均按执行服务（Temporal Schedule）的语义处理，每月不存在的日期同样遵循其日历。时间预览由执行服务计算，区分待保存、待生效、已生效、暂停和修改失败；服务不可用时说明暂时无法确认下次时间，不由浏览器估算。修改失败时提示原安排仍可能执行。首次同步失败后重试复用原安排，手动触发的响应丢失后重投不产生新的逻辑触发。

自动执行列表显示安排、启用与同步状态、下次时间和最近结果，支持修改、暂停或恢复和立即执行，并可进入执行历史、关联结果与失败原因；等待生效或修改失败时自动核对状态，不借查询重新发起执行。暂停只停止未来触发，取消正在进行的运行须使用该运行的取消操作。立即执行只表示触发已被接收，且使用已保存的安排，有未保存修改时须先保存。可能在一分钟内执行多次的安排，预览显示到秒并提示核对用量和重叠处理。删除安排停止未来调度，保留已有触发记录和运行来源。保存、删除、预览或触发安排需要执行服务可用，读取已有安排和运行不需要。

## 验收标准

A01–A18 是当前产品的可观察执行与证据合同。变更按影响范围运行对应回归；单个正常路径不能替代故障与边界验证。

| 编号 | 产品验收合同 |
| --- | --- |
| A01 | 接入第三个非金融插件，仅增加插件制品和配置即可被 Agent 使用；不修改或重新交付核心业务代码；插件可独立部署和升级。 |
| A02 | 未启用插件配置无效或启动失败时，通用 API、历史读取和无关 Agent 仍可使用；历史读取不初始化该插件。 |
| A03 | 同一 Agent 定义用于不同节点和 Workflow；修改依赖只修改节点；模型策略与确定性策略均通过统一契约执行，Agent 递归调用被拒绝。模型次数、工具次数和时间始终有界；累计模型用量可明确不设限，单次输出策略独立配置，调用间无隐式会话。 |
| A04 | 仅通过 inputMapping 或条件引用即可形成调度边；额外 dependsOn 与推导边合并；合并图中的环或无效引用在编译时被定位，编辑器显示边及来源。节点输入、Agent 输出及最终 Workflow 输出映射也遵守 schema 和显式缺失值语义。 |
| A05 | 独立分支实际并行；节点自身依赖满足后即可运行，无关慢分支不构成全局屏障；Workflow 并行不依赖模型并行工具能力。 |
| A06 | 依赖失败、条件跳过、允许缺失的汇聚和取消均具有确定结果；未产出的输出不被伪造，运行图能区分失败、依赖阻断和跳过。 |
| A07 | 在模型或工具结果确认保存后中断 Worker，恢复保留已确认调用和成功兄弟节点；Agent 后续工作继续执行，重试证据能区分节点、操作和网络尝试。 |
| A08 | 写操作响应丢失时保留同一 operationId 并记录 unknown；通过查询或去重核实效果；无法核实时保持可见未知状态，不盲目重复写入。并发投递不重复执行同一逻辑写入；后续尝试失败不会把既有 unknown 错记为效果未发生。 |
| A09 | 关闭浏览器不影响运行；取消请求阻止新调度并传播到活动调用，显示实际停止情况；重试不延长总 deadline，已发生效果不被描述为已撤销。重复取消只转发一次，终态提交保持完整；MCP 停止通知在有限时间内发送。 |
| A10 | 修改定义或发布插件后，已有 Run 仍使用冻结的定义、契约、授权和制品；绑定制品缺失时明确失败；成功输出不能被后续执行覆盖。冻结范围包括模型配置、非敏感资源及核心执行制品；不承诺外部数据或模型答案恒定。 |
| A11 | 同 Run 恢复可复用已确认结果；新 Run、rerun 和定时运行默认获取新数据；跨 Run 缓存只在显式策略允许时命中，并可检查来源及新鲜度。 |
| A12 | 在平台事务提交后、引擎启动前制造中断，恢复后启动命令不会丢失；重复投递不会产生第二个逻辑 Run；查询投影不能独立领取或恢复任务。 |
| A13 | 工具目录、模型声明和执行分发使用同一契约；同名工具跨插件不冲突；未经授权工具、资源或不符合 schema 的输入输出在边界被拒绝。 |
| A14 | 模型消息、快照、执行引擎 payload、读取、导出、日志及诊断不含原始凭据；模块间不传 ORM/Session 或万能 Context；Plugin 不直读核心私有表。Core 与插件双向保持私有数据和访问凭据边界。 |
| A15 | 可按 Run、节点、Agent 尝试、模型调用、工具操作和网络尝试检查输入输出与错误；依赖和产物来源可单独追溯，大产物通过不可变引用读取。外部追踪服务停止时，平台证据和内容寻址产物仍可读取。 |
| A16 | Temporal 是唯一执行引擎；它与 Prefect、Hatchet 的同场景比较及各探针的覆盖范围和限制见[执行引擎比较](执行引擎比较.md)，未测能力不记为验收通过。 |
| A17 | 定时触发按明确时区、重叠和错过策略运行，实际工作尚未完成时仍被计入重叠判断；每次触发保留来源和独立运行身份。 |
| A18 | 核心领域不依赖 HTTP/ORM/MCP 具体实现或插件业务代码；策略可通过小接口替换；业务差异通过定义和组合表达，执行状态与查询投影保持单向事实边界。 |

所有模式和独立插件页面还须满足以下操作合同；它们补充 A01–A18，不改变底层执行与证据边界。

| 范围 | 操作验收合同 |
| --- | --- |
| 任务与连接 | 符合公开契约的工作流可从普通表单开始并读到其声明的正文或保存回执；缺少连接时保留输入并可就地补齐；开始前自动展示本次有效设置，变更绑定需要可见确认，响应丢失后重试不重复创建 Run。 |
| 显示模式与输入复用 | 模式切换不写入任务、资源或计划，也不丢失已填字段、未完成输入或执行策略；离开返回保留内存草稿，刷新关闭前提示保存，服务器任务草稿可刷新恢复；命名配置、仅收藏和显式 `null` 输入可区分；定义变化保留旧输入并要求重新核对；复用历史输入保留原修订和来源。 |
| 结果与历史 | 正文、保存确认、缺失信息和真实状态优先显示；未知效果和取消请求可辨认，可能写入的未知结果重跑前需明确核实；跨页搜索、当地日期筛选、进入执行过程后返回及刷新均保留应有查询上下文；未确认重跑刷新后沿原命令身份恢复。 |
| 自动执行 | 从任务或结果继承输入，只有保存才启用；常用频率、组合日历、固定间隔、时区和执行策略通过控件可往返保留；时间预览区分待保存与已生效安排；暂停、手动触发、修改失败和来源按实际状态展示。 |
| 专家制作 | 字段、步骤、条件、来源、服务、预算和流程图共享同一工作流定义，文件导入导出无需源码编辑。 |
| 产品语言与恢复 | 所有页面、对话框、提示、错误、空状态、加载状态、结果及插件页面均不暴露平台实现细节，专家或折叠区域无例外；每一步说明当前状态、所需操作及后果，错误保留可执行的恢复方式，用户原文和业务附件不改写。 |

### 解耦验收

以下合同补充工作流解耦原则，A01–A18 继续适用。

| 编号 | 可观察合同 |
| --- | --- |
| D01 | 导入一个使用全新包名、Workflow 名和业务字段的合法包后，任务自动可发现，可完成输入、准备、执行、阅读结果及设置重复执行；无需修改 Core/前端代码或注册任务名单。 |
| D02 | 同一包经显式外部目录导入或普通导入得到相同内容修订及执行语义；重复初始化不覆盖操作者修订。平台默认不导入工作流，构建、启动与测试不依赖或引用 `demo/` 及其中内容；没有该目录时仍可导入和执行任意有效包。 |
| D03 | 表单标签、帮助和默认值随定义更新；保留未填、显式 null、空值及用户已填值的区别。合法但普通表单不支持的输入仍可完整编辑，不能导致任务消失或丢字段。 |
| D04 | 业务字段改名并同步声明后，结果仍按声明呈现；平台不因某个字段恰好叫 includeRisk、reportId 或 collection 而附加业务含义。正常跳过可选分支不自动等于业务资料不完整；真实失败、取消及 unknown 证据始终可见。 |
| D05 | 仅更新独立分发的工作流数据，不改变 Core 可执行制品 digest，也不要求重新构建前端；历史 Run 保留原包、展示声明、资源/插件绑定及 Core 制品身份。 |
| D06 | 插件离线时，已确认输出、通用产物与执行证据仍可读取；业务页面链接及专用业务解释由公开声明或插件提供，Core 不拼接 Finance/Notes 专用路由或读取其业务表。 |

## 验证边界

检查命令见 [`CONTRIBUTING.md`](../CONTRIBUTING.md#检查测试与构建)，各测试的覆盖归属见 [`backend/tests`](../backend/tests/AGENTS.md) 与 [`frontend/e2e`](../frontend/e2e/AGENTS.md) 的指南。

本地受控服务上的测试不证明外部模型与金融 provider 的真实可用性、额度和费用，执行成功也不代表研究质量；Finance K 线事件规则没有用真实行情评估准确率。Playwright 自动化和代理浏览器演练只证明实际演练过的场景，不代表真实用户研究。

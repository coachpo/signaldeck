# 产品说明

SignalDeck 是供可信单用户使用的个人 Agent 工作流平台。操作者在 Workflow Package 中定义可复用 Agent 和声明式 DAG，绑定模型与工具资源，手动或定时启动运行，并检查执行图、调用证据及产物。当前使用对象、部署和数据政策以 [`STATUS.md`](../STATUS.md) 为准。

本文是当前产品范围、行为和验收合同的权威。SD-TARGET-001 已实现并完成本地闭环验收，其产品要求归入本文；完成记录与历史基线见 [`STATUS.md`](../STATUS.md#已完成迭代)，技术边界见 [`架构说明`](架构说明.md)。

## 产品范围

核心导航包括 Dashboard、Workflow Packages、Resources、Plugins、Scheduled Tasks 和 Runs。Finance 的 Templates、Reports 和业务页面由独立 Finance 插件提供，Core 的 Plugins 页面可以打开插件公布的业务页面。

工作流定义根始终是 Workflow Package。当前包协议为 `signaldeck.workflowPackage/v2`，包中包含 `agents` 和 `workflows`。不提供认证/RBAC 产品面、多租户、插件市场、Studio、Tryout、memory、fork、portfolio、simulation 或 backtest。

## Workflow Packages

编辑器提供 YAML、Structure 和 Graph 视图。Structure 编辑包元数据及 Agent/Workflow JSON，应用草稿后更新同一 YAML；它不是另一套运行定义。Graph 显示编译后的依赖边及 `control`、`input`、`condition` 来源。校验诊断提供字段路径，并在可定位时提供 YAML 行列。

Agent 具有输入/输出 schema、工具和资源授权、执行预算以及一种策略：模型策略引用模型资源并使用 prompt；确定性策略调用一个已授权工具并映射输入和输出。Agent 不拥有节点依赖，可被包内不同节点或 Workflow 复用。节点通过 `uses` 引用 Agent，声明显式依赖、输入映射、条件、接受的上游终态和最大尝试次数；不能以递归 Agent/Workflow 调用扩展执行。每次调用的执行状态隔离，不保留隐式跨运行会话；模型轮数、工具次数、token 和总时限受预算约束，输入和最终结果须通过对应 schema。

控制、输入引用和条件引用共同形成 DAG，无需在显式依赖中重复声明已经引用的上游。输入映射和 Workflow 最终输出都支持引用、常量、对象、数组及显式缺失值处理，不执行任意代码或网络请求。编译器拒绝环、未知引用、不安全 YAML、无法满足的输入类型和不支持的 schema 约束。schema 使用固定的闭合子集，不接受任意 JSON Schema。保存生成内容寻址的包修订，后续编辑更新当前指针，不修改已有 Run 的定义。

启动页从已保存 Workflow 的输入 schema 生成输入表单并支持 JSON 编辑。启动会校验参数、工具契约、资源所有权和授权，冻结实际采用的定义、资源配置、凭据版本引用、插件发布和 Core 制品，再创建 Run。资源不可用或契约不匹配会返回明确错误；校验定义通过不承诺外部服务可用。

## Resources 与 Plugins

Resources 统一管理 `model` 和 `tool` 资源。模型资源支持 OpenAI-compatible `chat_completions` 和 `responses`，配置 endpoint、model ID 和 timeout；工具资源配置插件所有者、非敏感 scope、并发上限和请求速率。Agent 只能使用其授权的资源。有效工具集合同时受已启用且可用的插件发布、Agent 的工具选择及当前 Run 资源授权约束；跨插件同名工具以限定 Tool ID 区分。

凭据单独写入、加密保存。读取仅显示是否存在凭据和版本标识；编辑时不提交新凭据表示保留已有值。更新凭据会产生新版本，尚未完成的旧 Run 若再需要原版本，会明确失败为绑定已变化，不会静默使用新凭据。

Plugins 管理发布描述和启用状态，展示工具契约、制品身份及已有调用产生的健康观测。列出插件不会连接或初始化插件；没有观测时显示未观测，不宣称在线。新运行使用所需且启用的发布；历史运行保留其原发布身份。

当前独立制品为 Finance、Digital Oracle 和非金融 Notes。安装描述与业务进程部署是两个操作；保存描述不会自动构建或启动容器。插件可独立升级，但旧 Run 需要保留对应旧制品和 endpoint。插件编写、配置和升级契约见 [`writing-extensions.md`](writing-extensions.md)。

## Runs

Temporal 持有执行生命周期，浏览器关闭不会停止已接受的运行。就绪节点按各自依赖启动，受 Workflow 并发上限约束；无关慢分支不会形成全局步骤屏障。Agent 工具并发与外部资源限流分别控制。

Run 状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。节点和调用证据进一步区分 `blocked`、`skipped`、`timed_out`、`unknown` 等状态。条件为假产生跳过；不接受上游终态产生阻断；缺失输出必须按定义显式处理，不生成伪造结果。Workflow 可选择继续独立分支或失败后停止。

取消请求记录接受时间并通过引擎传播，界面区分“请求取消”和实际终态。重复取消不会重复转发同一执行操作的取消命令；已完成工作的终态证据提交后再传递取消，不留下永久 running 的 Agent 或节点记录。取消不能撤销已发生的外部效果。写调用响应丢失时保留原 `operationId` 和 `unknown`，先依赖插件查询或去重能力核实；无法确认时保留不确定结果，不盲目重写。同一逻辑操作的并发投递只允许一个执行所有者，其他投递在原 deadline 内等待确认；后续尝试被拒绝也不能抹去先前写入的未知状态。重试沿用原 deadline；具有写工具授权的 Agent 不通过整节点自动重启重新选择写操作。

Run Detail 分别提供运行依赖图、调用归属树、依赖/产物关系和不可变快照。证据可追溯节点、Agent、模型或工具操作以及网络尝试；大值以内容寻址产物引用展示并可读取。跨 Run 读缓存仅在 Agent 显式声明策略时使用，界面显示来源 Run/operation、获取时间和过期时间。恢复同一 Run 复用已确认调用与成功兄弟节点，继续后续工作；新运行默认重新获取数据。产物和通用历史记录独立于业务插件与外部追踪服务读取，成功节点的输出不能被覆盖。

Rerun 创建新 Run，保留原包修订、输入及来源 Run，重新解析当前资源、插件和 Core 制品，使用新的运行 deadline；它不会复制旧 Run 的执行结果。当前没有包或 Run 删除入口。

## Scheduled Tasks

计划选择包和 Workflow，保存参数 JSON、cron、IANA timezone、暂停状态、错过触发的 catch-up 时间窗，以及 `skip`、`buffer_one` 或 `allow` 重叠策略。日历和时区语义由 Temporal Schedule 执行；不再使用旧 interval/daily/weekly/monthly 或 placeholder 模板协议。

计划修改先保存期望配置，记录同步修订和失败状态，并可由 dispatcher 重试投递。每次 fire 有独立触发身份和关联 Run；计划动作等待实际 Run 生命周期结束，使重叠策略覆盖完整执行时间。手动 Trigger 使用稳定请求身份，响应丢失重投不会主动创建新的逻辑触发。

页面显示同步状态、触发历史、关联运行和失败原因。删除计划停止未来调度并保留已有 fire 和 Run 来源。计划保存或触发需要引擎可用，读取既有计划与运行不需要初始化插件。

## Finance 业务

Finance 独立页面和 API 拥有 Markdown Templates、模板编译、Reports 的创建、上传、读取和下载。普通业务报告按其 API 规则编辑；Agent 创建的报告保留调用来源，禁止覆盖或删除。市场数据和其他金融工具由 Finance 发布契约定义，金额、数量和市场价值使用字符串。Digital Oracle 拥有其市场研究 provider 与来源 warnings；上游不可用时不得伪造数据。

## 验收标准

以下编号沿用已完成迭代的 A01–A18，作为当前产品的可观察合同。后续变更按影响范围运行对应回归；单个正常路径或一个候选探针不能替代故障与边界验证。A16 的历史比较证据保留，实际产品回归针对已选定的 Temporal 组合。

| 编号 | 产品验收合同 |
| --- | --- |
| A01 | 接入第三个非金融插件，仅增加插件制品和配置即可被 Agent 使用；不修改或重新交付核心业务代码；插件可独立部署和升级。 |
| A02 | 未启用插件配置无效或启动失败时，通用 API、历史读取和无关 Agent 仍可使用；历史读取不初始化该插件。 |
| A03 | 同一 Agent 定义用于不同节点和 Workflow；修改依赖只修改节点；模型策略与确定性策略均通过统一契约执行，Agent 递归调用被拒绝。模型、工具次数和预算有界，调用间无隐式会话。 |
| A04 | 仅通过 inputMapping 或条件引用即可形成调度边；额外 dependsOn 与推导边合并；合并图中的环或无效引用在编译时被定位，编辑器显示边及来源。节点输入、Agent 输出及最终 Workflow 输出映射也遵守 schema 和显式缺失值语义。 |
| A05 | 独立分支实际并行；节点自身依赖满足后即可运行，无关慢分支不构成全局屏障；Workflow 并行不依赖模型并行工具能力。 |
| A06 | 依赖失败、条件跳过、允许缺失的汇聚和取消均具有确定结果；未产出的输出不被伪造，运行图能区分失败、依赖阻断和跳过。 |
| A07 | 在模型或工具结果确认保存后中断 Worker，恢复保留已确认调用和成功兄弟节点；Agent 后续工作继续执行，重试证据能区分节点、操作和网络尝试。 |
| A08 | 写操作响应丢失时保留同一 operationId 并记录 unknown；通过查询或去重核实效果；无法核实时保持可见未知状态，不盲目重复写入。并发投递不重复执行同一逻辑写入；后续尝试失败不会把既有 unknown 错记为效果未发生。 |
| A09 | 关闭浏览器不影响运行；取消请求阻止新调度并传播到活动调用，显示实际停止情况；重试不延长总 deadline，已发生效果不被描述为已撤销。重复取消只转发一次，终态提交保持完整；MCP 停止通知在有限时间内发送。 |
| A10 | 修改定义或发布插件后，已有 Run 仍使用冻结的定义、契约、授权和制品；绑定制品缺失时明确失败；成功输出不能被后续执行覆盖。冻结范围包括模型配置、非敏感资源及核心执行制品；不承诺外部数据或模型答案恒定。 |
| A11 | 同 Run 恢复可复用已确认结果；新 Run、rerun 和定时运行默认获取新数据；跨 Run 缓存只在显式策略允许时命中，并可检查来源及新鲜度。 |
| A12 | 在平台事务提交后、引擎启动前制造中断，恢复后启动命令不会丢失；重复投递不会产生第二个逻辑 Run；查询投影不能独立领取或恢复任务。 |
| A13 | 工具目录、模型声明和执行分发使用同一契约；同名工具跨插件不冲突；未经授权工具、资源或不符合 schema 的输入输出在边界被拒绝。 |
| A14 | 模型消息、快照、执行引擎 payload、读取、导出、日志及诊断不含原始凭据；模块间不传 ORM/Session 或万能 Context；Plugin 不直读核心私有表。Core 与插件双向保持私有数据和访问凭据边界。 |
| A15 | 可按 Run、节点、Agent 尝试、模型调用、工具操作和网络尝试检查输入输出与错误；依赖和产物来源可单独追溯，大产物通过不可变引用读取。外部追踪服务停止时，平台证据和内容寻址产物仍可读取。 |
| A16 | 保留 Temporal、Prefect、Hatchet 在相同场景下的适配与运行成本比较证据，明确不同探针的覆盖范围和限制；按用户已确定的 Temporal 组合验证动态 schema、并发隔离、取消传播、调用级恢复和固定制品恢复，不把选型决定或未测能力记为验收通过。 |
| A17 | 定时触发按明确时区、重叠和错过策略运行，实际工作尚未完成时仍被计入重叠判断；每次触发保留来源和独立运行身份。 |
| A18 | 核心领域不依赖 HTTP/ORM/MCP 具体实现或插件业务代码；策略可通过小接口替换；业务差异通过定义和组合表达，执行状态与查询投影保持单向事实边界。 |

## 验证边界

产品实现的回归入口包括 [`test_core_api.py`](../backend/tests/test_core_api.py)、[`test_dag_compiler.py`](../backend/tests/test_dag_compiler.py)、[`test_durable_runtime.py`](../backend/tests/test_durable_runtime.py)、[`test_target_schedules.py`](../backend/tests/test_target_schedules.py) 及 [`frontend/e2e`](../frontend/e2e/)。交付按 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 运行适用检查和本地集成，为受影响的上述验收合同保留可重复的实际证据。调用恢复、并发写入和取消还分别由 `test_operation_redelivery.py`、`test_tool_gateway_unknown_reconcile.py`、`test_repeat_workflow_cancellation.py`、`test_terminal_projection_cancellation.py` 和 `test_mcp_cancellation.py` 等回归覆盖。

外部模型与金融 provider 的真实可用性、容量和费用不由本地受控服务测试证明。当前编辑器的结构视图仍使用 JSON 编辑 Agent/Workflow，资源配置也使用 JSON；它们不是完整拖拽式图编辑器或模型能力探测界面。

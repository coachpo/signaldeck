# 产品说明

SignalDeck 是供可信单用户使用的个人 Agent 工作流平台。普通操作从选择任务、填写业务信息开始，执行后阅读结果并可安排重复执行；专家通过助手、步骤、条件、资料来源、服务和预算控件制作可复用工作流，并检查执行过程。当前使用对象、部署和数据政策以 [`STATUS.md`](../STATUS.md) 为准。

本文是当前产品范围、行为和验收合同的权威。SD-TARGET-001 已实现并完成本地闭环验收，其产品要求归入本文；完成记录与历史基线见 [`STATUS.md`](../STATUS.md#已完成迭代)，技术边界见 [`架构说明`](架构说明.md)。

## 产品范围

默认普通模式的核心导航为**任务、结果、设置**。任务页发现所有已保存的 Workflow，并提供常用配置和自动执行入口；可选示例包含市场研究、综合资料研究、整理笔记、保存原文；结果页提供历史查询及正文阅读；设置管理显示偏好、新安排的默认时区和已连接服务。专家模式增加工作流制作、服务连接、扩展服务等入口；任务首页的“全部任务定义与专家制作”也随专家模式显示。普通/专家是展示偏好，不是权限划分，不改变执行能力或已有配置。

Finance 的格式、报告和业务页面仍由独立 Finance 插件提供；已连接服务和插件管理可以打开插件公布的页面，具体报告也可从结果直达。

所有显示模式及独立插件页面均使用业务语言表达操作、状态和恢复方式。页面、表单、弹窗、提示、错误、空状态、加载状态和结果详情不得展示平台内部 ID、原始 API 响应、堆栈、存储路径、schema、调度引擎或资源绑定等实现信息；折叠区和专家模式也不例外。受支持的操作必须通过适当控件完成，不能要求用户编写 JSON、YAML 或 cron，不能只重命名术语、补长篇解释或删减能力。工作流文件导入/导出保留现有格式，用户无需阅读或编写源码。用户自己的正文、代码和原始业务附件按原文保留；其内容不作为平台技术展示的过滤对象。

工作流定义根始终是 Workflow Package。当前包协议为 `signaldeck.workflowPackage/v2`，包中包含 `agents` 和 `workflows`。不提供认证/RBAC 产品面、多租户、插件市场、Studio、Tryout、memory、fork、portfolio、simulation 或 backtest。

## 工作流与平台解耦原则

SignalDeck 的产品定位是通用工作流执行平台。所有工作流，包括预置、导入、自定义、手动及定时执行的工作流，都是遵循公开契约的数据定义；平台与具体工作流不得互相依赖其实现。任务发现、输入、结果和数据分发均按下列原则实现；历史展示差异及大产物选择限制见[架构边界](架构说明.md#工作流边界与已知偏差)。

- 平台负责通用的定义管理、校验、编译、资源绑定、执行、调度、证据存储和呈现。任务发现、输入编辑及结果阅读都必须适用于符合契约的任意工作流，不能依赖具体包、Workflow、插件的预置名单或业务字段名称。
- 工作流的业务输入、默认值、提示词、DAG、业务条件及展示声明属于包数据；外部业务操作、数据和专用页面属于独立插件。新增或更新使用现有平台能力的工作流，只需交付定义及所需插件/资源配置，不应修改或重新发布 Core 或前端。
- 工作流可以引用公开且版本明确的包、schema、工具、资源及展示契约；这种契约依赖不等于实现耦合。工作流及其业务实现不得导入 Core 私有模块、访问 Core 私有表、调用特定 Worker 内部函数，或依赖内置任务页面才能执行。
- 预置只是可选的数据分发与导入方式，与用户创建的定义使用相同的校验、修订和运行路径。平台在没有任何预置包时仍能启动、导入及执行其他有效包；预置数据不属于 Core 可执行制品。
- 所有模式提供覆盖合法输入的通用值控件，保留任务可发现性、完整字段和数组、标量、空值的编辑能力，无需切换模式或编辑源码。未声明专用展示时仍可读取通用业务输出和执行过程；平台不根据业务字段猜测报告、笔记、风险分析或业务完整性。业务告知与平台记录的失败、跳过、取消及未知效果分别表达。

新的通用能力可能需要演进平台契约；演进须面向同类工作流的共同需求，不能为某个工作流增加专用入口。具体技术约束见[开发规范](开发规范.md#工作流解耦规则)，设计取舍、版本和实现证据见[工作流解耦方案](工作流解耦方案.md)。

## 任务与常用配置

任务首页直接枚举已保存的全部 Workflow，显示最近一次执行的时间、状态和结果入口；任务与常用配置可按名称搜索。名称、说明、字段标题及静态提示来自所选定义，不需要额外登记场景。以下四个场景保留为示例与回归覆盖，不是平台支持的工作流白名单；实际字段约束以所选 Workflow 的输入 schema 为准。

| 场景 | 业务输入 | 结果与保存位置 |
| --- | --- | --- |
| 市场研究 | 研究对象、研究问题、是否包含风险分析 | 研究正文、行情及 Finance 报告；风险分支可选，正常跳过与失败分别显示。 |
| 综合资料研究 | 研究问题 | 多来源研究正文及 Finance 报告，保留来源、未回答问题和上游限制。 |
| 整理笔记 | 标题、原文、查找已有笔记的关键词、是否整理总结 | 保存后的笔记正文、回执与所属集合。 |
| 保存原文 | 标题、原文 | 确定性保存笔记正文与回执，不需要模型服务。 |

这些场景是现有包和 Workflow 的业务展示，不形成另一套定义。输入采用递归字段、列表、文本、数值、开关、选项和空值控件，不隐藏任务或静默忽略字段；对象、数组、标量和显式 `null` 均保留。字段顺序取显式 `presentation.inputHints` 的排列，嵌套组按首个后代提示的位置排列，未声明字段保持原相对顺序；排序只影响呈现，不改字段键或提交内容。schema/2 默认值只用于新草稿，准备/提交消费同一份显式参数；已有草稿、常用配置、历史复用及计划参数不补值。字段校验保留必填、可选、默认值和实际输入的区别。模式切换保留当前已填内容、未完成输入及执行设置，修改兄弟字段不会补回省略字段或改写现有值。

任务页可显式保存、恢复和删除草稿，包括尚未通过校验的输入。历史草稿中的未应用原稿先由用户明确恢复，再用结构化控件继续；无法读取的原稿保留下载和明确放弃的选择，不擅自覆盖已经确认的输入。草稿保留原包修订、来源 Run 和参数缺失/显式 null 的区别，不补默认值；当前定义变更时显示提示，启动仍使用原修订并重新校验。多窗口更新使用修订冲突提示，不覆盖另一窗口修改。启动前持久化原请求身份，响应不确定时恢复后锁定输入并沿同一请求重试；草稿、常用配置与任务收藏分别管理。

业务输入通过基本校验后自动显示准备检查，列出缺少的连接、本次业务范围、保存位置、预算与授权；配置已就绪且没有待确认变化时，可直接开始任务。普通模式自动核对就绪后隐藏独立核对按钮；专家模式、未应用草稿、准备或提交错误及未就绪时保留该入口，并继续遵守草稿应用与提交状态限制。准备检查只读取安全配置及发布描述，不探测外部服务；“已有配置”与最近调用观测分别展示；没有记录时明确未观测，已有成功、失败或未知记录附观测时间，历史成功不表示当前在线。模型观察只匹配当前资源的配置与凭据版本，显示实际调用时间和证据入口；更换配置或凭据后，旧观察不会成为新连接的状态。

资源连接预设分别显示加载、失败、无候选、待选择和已选择状态；有候选时要求显式选择，不自动选择首项。连接可以在当前任务从已部署服务预设选择、自行填写或复用其他连接的非敏感设置，确认业务范围并单独写入凭据，保留业务输入后再次检查。没有预设时仍可通过连接控件补齐配置；插件进程未部署或发布未登记时仍需完成实际部署/登记，界面不会通过保存描述伪造在线状态。检查生成的绑定标识由平台在启动时内部核对，期间连接或发布发生变化时要求用户重新核对可读设置；请求结果不确定时保留已提交输入和原启动身份，核实前禁止修改这次输入，重试不能变成第二次执行。

未保存的业务草稿通过当前应用会话内存保留，离开后返回或切换模式可继续；刷新或关闭前提示尚未保存，不承诺刷新后恢复未保存内容。任务显式保存的服务器草稿可刷新后从目录恢复。用户可主动保存命名常用配置，也可只收藏任务而不保存输入；常用配置保留包/Workflow、校验版本、业务输入和收藏/置顶状态，保存不执行任务、不启用计划。定义变化后读取保留原字段并给出重校验状态；保存时当前版本不符会被阻断，需核对后更新。保存的显式 `null` 输入与未保存输入的收藏不同。删除配置或取消收藏不删除包、计划、历史或结果，凭据始终通过连接单独管理。浏览器持久存储不保存业务输入或凭据；显示模式、默认时区等偏好独立保存。未确认重跑可在本标签页保存原命令身份和核对令牌，刷新后从服务器重取业务输入，避免产生重复执行。

## Workflow Packages

专家编辑器通过工作流、助手和步骤进行制作，提供新增/删除、工作说明、模型和工具选择、服务访问、字段规则、执行顺序、条件、资料来源、结果分节、预算及并发/重试限制等控件。字段、固定值、来源与缺失处理均使用结构化编辑；复杂能力不以源码输入替代。删除仍被引用的对象前先提示调整相关内容，实际删除需确认。控件修改写入同一 YAML 文档，不形成另一套运行定义。导入文件先经过服务端检查，失败保留当前草稿，通过后明确确认替换；导出保留当前完整原格式及用户正文。切换页面和模式保留当前草稿，刷新或关闭前提醒先保存。

流程图消费编译后的依赖关系，提供分层布局、缩放、平移和步骤定位，以执行顺序、资料来源和执行条件表达关联原因。它不是通过拖拽改变调度语义的图制作协议。界面将校验问题定位到相应工作流、助手、步骤或字段，并说明可执行的修正方向；源码路径、行列和编译诊断仍由底层合同保留，不直接呈现在产品界面。

Agent 具有输入/输出 schema、工具和资源授权、执行预算以及一种策略：模型策略引用模型资源并使用 prompt；确定性策略调用一个已授权工具并映射输入和输出。Agent 不拥有节点依赖，可被包内不同节点或 Workflow 复用。节点通过 `uses` 引用 Agent，声明显式依赖、输入映射、条件、接受的上游终态和最大尝试次数；不能以递归 Agent/Workflow 调用扩展执行。每次调用的执行状态隔离，不保留隐式跨运行会话；模型轮数、工具次数、token 和总时限受预算约束，输入和最终结果须通过对应 schema。

控制、输入引用和条件引用共同形成 DAG，无需在显式依赖中重复声明已经引用的上游。输入映射和 Workflow 最终输出都支持引用、常量、对象、数组及显式缺失值处理，不执行任意代码或网络请求。编译器拒绝环、未知引用、不安全 YAML、无法满足的输入类型和不支持的 schema 约束。schema 使用固定的闭合子集，不接受任意 JSON Schema。保存生成内容寻址的包修订，后续编辑更新当前指针，不修改已有 Run 的定义。

启动页从已保存 Workflow 的输入 schema 生成通用输入控件。启动会校验参数、工具契约、资源所有权和授权，冻结实际采用的定义、资源配置、凭据版本引用、插件发布和 Core 制品，再创建 Run。界面以需要补齐的字段、服务连接或访问权限说明问题；校验定义通过不承诺外部服务可用。

工作流可声明 `presentation/1` 输入提示、运行标题和结果分节；schema 注解使用显式 `x-signaldeck-schema: signaldeck.schema/2`。未知版本、字段、无效默认值或选择器在保存时带源码位置拒绝，缺省新字段不改变旧包 hash。具体闭合格式见[解耦契约](工作流解耦方案.md#设计定案)。

## Resources 与 Plugins

Resources 统一管理 `model` 和 `tool` 资源。模型资源支持 OpenAI-compatible `chat_completions` 和 `responses`，配置 endpoint、model ID 和 timeout；工具资源配置插件所有者、非敏感 scope、并发上限和请求速率。Agent 只能使用其授权的资源。有效工具集合同时受已启用且可用的插件发布、Agent 的工具选择及当前 Run 资源授权约束；跨插件同名工具以限定 Tool ID 区分。

服务以名称和用途展示，通过服务选择、业务范围、连接设置、请求限制及独立凭据控件配置；内部标识由平台维护。凭据单独写入、加密保存，读取仅显示是否已经配置；编辑时不提交新凭据表示保留已有值。更新凭据会产生新版本，尚未完成的旧 Run 若再需要原版本，会明确提示连接已变化、需要重新核对，不会静默使用新凭据，也不向界面展示版本标识。

插件管理通过安装文件接入已有服务，展示可用能力、启用状态、业务页面和已有调用产生的健康观测，不展示原始发布描述、工具 schema 或制品身份。列出插件不会连接或初始化插件；没有调用记录时如实说明，不宣称在线。新运行使用所需且启用的发布；历史运行保留其原发布身份。

当前独立制品为 Finance、Digital Oracle 和非金融 Notes。安装描述与业务进程部署是两个操作；保存描述不会自动构建或启动容器。插件可独立升级，但旧 Run 需要保留对应旧制品和 endpoint。插件编写、配置和升级契约见 [`writing-extensions.md`](writing-extensions.md)。

## Runs

Temporal 持有执行生命周期，浏览器关闭不会停止已接受的运行。就绪节点按各自依赖启动，受 Workflow 并发上限约束；无关慢分支不会形成全局步骤屏障。Agent 工具并发与外部资源限流分别控制。

Run 状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。节点和调用证据进一步区分 `blocked`、`skipped`、`timed_out`、`unknown` 等状态。条件为假产生跳过；不接受上游终态产生阻断；缺失输出必须按定义显式处理，不生成伪造结果。Workflow 可选择继续独立分支或失败后停止。

取消请求记录接受时间并通过引擎传播，界面区分“请求取消”和实际终态。重复取消不会重复转发同一执行操作的取消命令；已完成工作的终态证据提交后再传递取消，不留下永久 running 的 Agent 或节点记录。取消不能撤销已发生的外部效果。写调用响应丢失时保留原 `operationId` 和 `unknown`，先依赖插件查询或去重能力核实；无法确认时保留不确定结果，不盲目重写。同一逻辑操作的并发投递只允许一个执行所有者，其他投递在原 deadline 内等待确认；后续尝试被拒绝也不能抹去先前写入的未知状态。重试沿用原 deadline；具有写工具授权的 Agent 不通过整节点自动重启重新选择写操作。

结果详情提供步骤进度、执行过程、资料与附件及本次设置，按冻结的助手名称、步骤关系、实际状态、时间和尝试次数追溯工作。输入、工作要求、服务访问和执行限制采用可读摘要，不呈现原始请求、响应、元数据或不可变快照源码。底层节点、Agent、模型或工具操作和网络尝试身份继续保留，导航在内部使用这些身份。大值作为附件读取；跨 Run 读缓存仅在 Agent 显式声明策略时使用，界面显示来源任务链接、取得时间和可复用至的时间。恢复同一 Run 复用已确认调用与成功兄弟节点，继续后续工作；新运行默认重新获取数据。产物和通用历史记录独立于业务插件与外部追踪服务读取，成功节点的输出不能被覆盖。

结果详情先显示已确认正文或保存确认，并列出来源、数据时间、执行时间、缺失内容、附件及实际运行状态；未取得数据时间时不以运行时间冒充。正文来自最终输出或已确认的节点、工具输出；尚未完成或失败节点的模型文本不提升为已完成结果。声明正文、历史正文和文本附件共用 Markdown 排版，保留标题、清单、表格、代码与链接；长表格和代码可通过键盘横向阅读。原始业务 JSON 附件保持字面值阅读，不将字符串解释为 Markdown；大文本或业务 JSON 产物可在结果页读取或下载。`unknown` 依据本 Run 冻结的工具 effect 区分只读结果未确认与可能写入；只读失败不提示“可能保存”，写入未知仍要求核实，历史缺少可靠 effect 时保持保守。取消请求也不被称为已停止。失败或取消的运行可以保留已确认的局部产物；已确认的模型错误可区分额度、认证、限流、模型不可用、输入、输出超限及未知原因，并显示处理方向；无分类依据的历史错误不补推原因，也不展示原始错误码。保存回执说明确认状态，不把平台操作身份或原始回执对象作为正文。报告链接使用该 Run 冻结的插件页面和已确认报告身份；所属插件不可用时，Core 历史与已有通用产物仍可读取。

结果分节由冻结声明选择最终输出或已确认节点输出，保留节点、工具操作及插件归属。正常跳过、业务告知/缺失、执行失败/取消及未知效果分别显示。插件深链接只能使用冻结发布的 `resultLink/1` 契约，不能从业务字段拼接。无声明的历史包保留通用值、文本/JSON 产物及执行证据，原先推测的专用正文/标题/链接不再生成；不修改旧快照。大产物中的选择标记为待展开，可阅读/下载原确认内容，不伪造资料缺失。

历史在服务器端对业务标题、任务/运行标识和 Run 已存输出字段进行字面搜索，界面通过标题、状态、任务、来源和日期寻找结果，无需输入内部标识。历史可按“进行中”或“需要处理”分组，按时间或标题排序及分页。“需要处理”包括失败运行和仍有逻辑调用结果或效果未知的运行，已核实的旧网络尝试不单独构成未知结果。日期筛选按浏览器当地日历日转换查询边界。进入结果和执行过程后返回会保留筛选与页码；查询以返回的创建时间上界固定新运行纳入范围，刷新保留筛选、回到第一页并纳入新增运行。

Rerun 创建新 Run，保留原包修订、输入及来源 Run，重新解析当前资源、插件和 Core 制品，使用新的运行 deadline；它不会复制旧 Run 的执行结果。当前没有包或 Run 删除入口。重跑前以可读业务摘要展示原设置与本次服务或范围变化；原结果含可能写入的 `unknown` 时，用户须先勾选已核实目标位置和执行过程，才能确认再次执行；冻结为 read 的结果未知不要求核实不存在的保存。重跑响应不确定时，进入执行过程再返回或刷新同一标签页，仍沿用原命令身份及核对令牌，业务输入重新从原记录读取。“修改输入后开始”装载原包修订和输入，按原 schema 校验后创建有 `sourceRunId` 的新运行，不改写原输入或结果。

所有模式的结果页均优先展示正文、真实状态、来源与缺失信息；完整业务输入以字段标签和值呈现，业务范围与服务变化直接可见。复制和 Markdown 导出使用冻结的确认分节，无声明历史保留通用业务值；文件保留运行状态、来源和时间，以可读链接返回完整结果；链接的内部寻址字段不作为正文显示。无展示声明时，完全相等的确认内容聚合阅读和默认复制/导出，保留全部来源步骤入口；显式声明的不同分节不合并。字符串按原文交付，不因缺少 Markdown 声明而被称为没有正文。附件需显式读取选入，未选内容与延后解析声明会列明，未读取的所选附件不能当作完整内容导出。原始业务附件不改写；复制或下载失败保留选择供重试，不替代 Finance 的原下载入口。

每次运行和浏览器当地日提供已报告输入/输出 token、逻辑调用数、耗时、缺少用量及网络尝试覆盖说明；同一逻辑调用的模型与网络证据不重复相加。缺值显示未知，不冒充零消耗、余额或供应商账单。今日按逻辑调用首次开始时间及明确 IANA 时区归属，跨日重试不重复计入两天。Agent 预算可单独设置可选的 `maxOutputTokens` 单次输出上限，实际请求同时受剩余总 token 约束。模型资源通过公开、闭合的 provider 能力配置选择协议输出限制字段并随 Run 冻结；读取不探测服务或根据模型名称推断。供应商报告输出用量超过实际请求上限时，该 Agent 明确失败，不继续模型或工具调用，不把违规响应提升为成功结果；已发生调用及已报告用量仍保留，其他分支沿原 failurePolicy 处理。缺少 usage 保持未知，截断或请求字段存在本身不证明成功。省略新配置保持旧序列化，资源更新只影响之后重新绑定的运行。

结果可收藏、标为已读/未读、编辑个人备注，并沿用历史搜索、分页、日期和筛选上下文。标记是独立附属数据，不改运行、快照或正文；多窗口修订冲突需读取最新状态后确认，备注草稿保留。标为结果已读同时确认当时的执行更新，后续状态变化仍产生新更新。

“执行更新”入口列出现有记录的当前完成、失败、取消或待核实状态，以及没有生成 Run 的 fire 启动失败。重复读取不生成重复项或启动执行；已查看的 unknown 仍在待处理范围，核实后的状态产生新的未读身份。它是当前事实列表，不是完整事件日志；发生变化的旧状态不保留为历史通知副本。

比较页固定两个 Run 与两侧选定分节，可从服务端历史搜索分页选择。两侧分别保留状态、原修订、输入、来源与时间；文本差异只说明原文不同，不生成业务结论。大产物必须显式读取；过长变更区按完整段落显示删除与新增，不静默截断或修改原输出。

## Notes 资料工作区

Notes 独立页面提供只读集合浏览、标题/正文的字面搜索、稳定分页、详情和复制，并显示原始、派生或历史未分类来源及已确认的来源笔记引用。来源链接使用笔记标题，不显示保存标识；来源暂不可读取时明确说明目前不能核对，并提供重新查看。页面默认排除派生内容，可显式选择包含；历史未分类笔记仍可查看，不按标题或正文猜测类别。读取复用已有不可变笔记，不增加修改、删除或隐式记忆。新发布通过公开 pageUrl/resultLink 描述页面，新的 Notes 工作流结果可直达确认笔记；旧 Run 保留原冻结发布和链接。Notes 离线时，Core 已确认正文、导出、比较和个人标记仍可使用。整理笔记包显式排除派生内容作为默认检索策略，普通输入允许选择包含；保存原文标记原始来源，总结标记派生来源并引用本次确认检索的笔记。固定原始资料下，新 Run、重跑和定时运行重新检索，不自动把先前总结作为新输入；新增原始资料仍可被后续运行找到，不合并或改写原始矛盾。来源、笔记与操作回执在插件内原子保存，具体合同见[插件接入](writing-extensions.md#notes-来源与检索合同)。

## Scheduled Tasks

任务或结果可以发起“设置重复执行”，继承任务和输入，名称可修改，只有主动保存才创建计划。频率控件提供每天、每周、每月，组合日期与时刻可选择月份、日期、星期、小时、分钟、秒和年份，也可设置固定间隔及参考起点；支持多选和按范围/间隔批量选择，不要求填写时间表达式。控件保存为现有 cron 和 IANA timezone，未修改的合法规则保持原值，每月不存在的日期遵循执行服务日历。无法读取的旧规则保留原安排，用户可通过频率控件明确重设，不因修改名称或输入而覆盖。新安排仅在首次初始化采用显示时区偏好；已保存的时区不因偏好或浏览器所在地变化被改写。

计划仍保存包、Workflow、参数、cron、IANA timezone、暂停状态、错过触发的 catch-up 时间窗，以及 `skip`、`buffer_one` 或 `allow` 重叠策略。界面通过“上次尚未完成时如何处理”和“错过后多久仍需补执行”等控件表达这些选择，修改频率不覆盖已有策略。控件只转换现有 cron 合同，没有恢复旧 interval/daily/weekly/monthly 或 placeholder 执行协议。日历、夏令时、重叠和补触发均由 Temporal Schedule 执行。

时间预览由 Temporal 返回，界面区分待保存、待生效、已生效、暂停和修改失败；预览服务不可用时明确说明暂时无法确认下次时间，不由浏览器估算。预期修订与已同步修订不一致时，旧的已生效时间不能表示新配置已生效；保存失败须提示之前的安排仍可能执行，不展示调度引擎或内部修订。

计划修改先保存期望配置，记录同步修订和失败状态，并可由 dispatcher 重试投递。每次 fire 有独立触发身份和关联 Run；计划动作等待实际 Run 生命周期结束，使重叠策略覆盖完整执行时间。手动 Trigger 使用稳定请求身份，响应丢失重投不会主动创建新的逻辑触发。新建安排同样使用稳定 `requestId`；首次同步失败后重试复用原安排，不递增修订或重复创建，相同身份提交不同定义返回冲突。

自动执行列表显示安排、启用和同步状态、下次时间与最近结果，支持修改、暂停/恢复和立即执行，并进入执行历史、关联结果及失败原因。等待生效或修改失败时自动核对已有状态，服务恢复后更新显示，不通过查询重新发起执行。暂停只停止未来触发，取消当前运行需使用运行的取消动作。立即执行返回触发接收状态，不代表运行已完成；有未保存修改时先保存再执行。秒级安排的时间预览显示秒，可能在一分钟内执行多次时提示核对用量和重叠处理。删除计划停止未来调度并保留已有 fire 和 Run 来源。计划保存或触发需要引擎可用，读取既有计划与运行不需要初始化插件。

## Finance 业务

Finance 独立页面和 API 拥有 Markdown Templates、模板编译、Reports 的创建、上传、读取和下载。默认普通页面用于报告阅读和“使用已有格式”：选择格式、填写必填/可选业务字段、预览，再生成新报告。生成会核对已预览的模板及编译内容，期间格式或被引用报告变化须重新预览。列表提供字面搜索、排序与分页；报告支持名称、slug 和正文搜索及既有业务筛选，具体报告可按 slug 或报告 ID 深链接直达并下载原文。

专家模式提供格式制作、业务字段、报告引用和预览控件，以及现有上传和普通报告编辑入口。字段填写业务名称并设置必填或可选，内部键自动生成；正文中的字段和引用以可读名称标记，选择报告范围及所需内容即可插入，不要求手写表达式。底层模板仍以输入注释和引用表达字段合同，未声明的输入引用按必填处理；未修改的模板原文往返保留，普通报告编辑、上传和下载不改写原文。制作区先于试用预览，未保存格式须先保存，再预览并生成。来源只展示业务说明、作者、标签、研究对象和日期，不展示原始元数据。普通/专家和条目切换保留本页内存草稿，不产生写操作；刷新或关闭前提醒保存，不将业务草稿持久化到浏览器。保存、生成、上传或删除尚未完成时，页面暂时锁定模式、当前条目和草稿编辑，失败后保留草稿并恢复操作；保存结果不确定时先核对已有报告，避免重复生成。普通业务报告按其 API 规则编辑；Agent 创建的报告保留调用来源，禁止覆盖或删除。市场数据和其他金融工具由 Finance 发布契约定义，金额、数量和市场价值使用字符串。Digital Oracle 拥有其市场研究 provider 与来源 warnings；上游不可用时不得伪造数据。

## 验收标准

以下编号沿用已完成迭代的 A01–A18，作为当前产品的可观察合同。后续变更按影响范围运行对应回归；单个正常路径或一个候选探针不能替代故障与边界验证。A16 的历史比较证据保留，实际产品回归针对已选定的 Temporal 组合。

| 编号 | 产品验收合同 |
| --- | --- |
| A01 | 接入第三个非金融插件，仅增加插件制品和配置即可被 Agent 使用；不修改或重新交付核心业务代码；插件可独立部署和升级。 |
| A02 | 未启用插件配置无效或启动失败时，通用 API、历史读取和无关 Agent 仍可使用；历史读取不初始化该插件。 |
| A03 | 同一 Agent 定义用于不同节点和 Workflow；修改依赖只修改节点；模型策略与确定性策略均通过统一契约执行，Agent 递归调用被拒绝。模型、工具次数和预算有界，调用间无隐式会话。 |
| A04 | 仅通过 inputMapping 或条件引用即可形成调度边；额外 dependsOn 与推导边合并；合并图中的环或无效引用在编译时被定位，编辑器显示边及来源。节点输入、Agent 输出及最终 Workflow 输出映射也遵守 schema 和显式缺失值语义。 |
| A05 | 独立分支实际并行；节点自身依赖满足后即可运行，无关慢分支不构成全局屏障；Workflow 并行不依赖模型并行工具能力。 |
| A06 | 依赖失败、条件跳过、允许缺失的汇聚和取消均具有确定结果；未产出的输出不被伪造，运行图能区分失败、依赖阻断和跳过。 |
| A07 | 在模型或工具结果确认保存后中断 Worker，恢复保留已确认调用和成功兄弟节点；Agent 后续工作继续执行，重试证据能区分节点、操作和网络尝试。 |
| A08 | 写操作响应丢失时保留同一 operationId 并记录 unknown；通过查询或去重核实效果；无法核实时保持可见未知状态，不盲目重复写入。并发投递不重复执行同一逻辑写入；后续尝试失败不会把既有 unknown 错记为效果未发生。 |
| A09 | 关闭浏览器不影响运行；取消请求阻止新调度并传播到活动调用，显示实际停止情况；重试不延长总 deadline，已发生效果不被描述为已撤销。重复取消只转发一次，终态提交保持完整；MCP 停止通知在有限时间内发送。 |
| A10 | 修改定义或发布插件后，已有 Run 仍使用冻结的定义、契约、授权和制品；绑定制品缺失时明确失败；成功输出不能被后续执行覆盖。冻结范围包括模型配置、非敏感资源及核心执行制品；不承诺外部数据或模型答案恒定。 |
| A11 | 同 Run 恢复可复用已确认结果；新 Run、rerun 和定时运行默认获取新数据；跨 Run 缓存只在显式策略允许时命中，并可检查来源及新鲜度。 |
| A12 | 在平台事务提交后、引擎启动前制造中断，恢复后启动命令不会丢失；重复投递不会产生第二个逻辑 Run；查询投影不能独立领取或恢复任务。 |
| A13 | 工具目录、模型声明和执行分发使用同一契约；同名工具跨插件不冲突；未经授权工具、资源或不符合 schema 的输入输出在边界被拒绝。 |
| A14 | 模型消息、快照、执行引擎 payload、读取、导出、日志及诊断不含原始凭据；模块间不传 ORM/Session 或万能 Context；Plugin 不直读核心私有表。Core 与插件双向保持私有数据和访问凭据边界。 |
| A15 | 可按 Run、节点、Agent 尝试、模型调用、工具操作和网络尝试检查输入输出与错误；依赖和产物来源可单独追溯，大产物通过不可变引用读取。外部追踪服务停止时，平台证据和内容寻址产物仍可读取。 |
| A16 | 保留 Temporal、Prefect、Hatchet 在相同场景下的适配与运行成本比较证据，明确不同探针的覆盖范围和限制；按用户已确定的 Temporal 组合验证动态 schema、并发隔离、取消传播、调用级恢复和固定制品恢复，不把选型决定或未测能力记为验收通过。 |
| A17 | 定时触发按明确时区、重叠和错过策略运行，实际工作尚未完成时仍被计入重叠判断；每次触发保留来源和独立运行身份。 |
| A18 | 核心领域不依赖 HTTP/ORM/MCP 具体实现或插件业务代码；策略可通过小接口替换；业务差异通过定义和组合表达，执行状态与查询投影保持单向事实边界。 |

所有模式和独立插件页面还须满足以下可观察合同；这些合同补充 A01–A18，不改变底层执行与证据边界。

| 范围 | 操作验收合同 |
| --- | --- |
| 任务与连接 | 四个首批场景可从普通表单开始并读到正文或保存回执；缺少连接时保留输入并可就地补齐；开始前自动展示本次有效设置，变更绑定需要可见确认，响应丢失后重试不重复创建 Run。 |
| 显示模式与输入复用 | 模式切换不写入任务、资源或计划，也不丢失已填字段、未完成输入或执行策略；离开返回保留内存草稿，刷新关闭前提示保存，服务器任务草稿可刷新恢复；命名配置、仅收藏和显式 `null` 输入可区分；定义变化保留旧输入并要求重新核对；复用历史输入保留原修订和来源。 |
| 结果与历史 | 正文、保存确认、缺失信息和真实状态优先显示；未知效果和取消请求可辨认，可能写入的未知结果重跑前需明确核实；跨页搜索、当地日期筛选、进入执行过程后返回及刷新均保留应有查询上下文；未确认重跑刷新后沿原命令身份恢复。 |
| 自动执行 | 从任务或结果继承输入，只有保存才启用；常用频率、组合日历、固定间隔、时区和执行策略通过控件可往返保留；时间预览区分待保存与已生效安排；暂停、手动触发、修改失败和来源按实际状态展示。 |
| 专家制作与 Finance | 字段、步骤、条件、来源、服务、预算和流程图共享同一工作流定义，文件导入导出无需源码编辑；Finance 字段和引用采用业务控件，预览与生成核对当前内容，写入期间保护草稿，Agent 报告不可覆盖或删除。 |
| 产品语言与恢复 | 所有页面、对话框、提示、错误、空状态、加载状态、结果及插件页面均不暴露平台实现细节，专家或折叠区域无例外；每一步说明当前状态、所需操作及后果，错误保留可执行的恢复方式，用户原文和业务附件不改写。 |

### 解耦验收

以下合同补充工作流解耦原则。本次实现证据与真实回归记录见[工作流解耦方案](工作流解耦方案.md#验证记录)，A01–A18 继续保持原有执行与证据约束。

| 编号 | 可观察合同 |
| --- | --- |
| D01 | 导入一个使用全新包名、Workflow 名和业务字段的合法包后，任务自动可发现，可完成输入、准备、执行、阅读结果及设置重复执行；无需修改 Core/前端代码或注册任务名单。 |
| D02 | 同一包经预置导入或普通导入得到相同内容修订及执行语义；重复初始化不覆盖操作者修订。未安装预置包时，平台及其他工作流仍可使用。 |
| D03 | 表单标签、帮助和默认值随定义更新；保留未填、显式 null、空值及用户已填值的区别。合法但普通表单不支持的输入仍可完整编辑，不能导致任务消失或丢字段。 |
| D04 | 业务字段改名并同步声明后，结果仍按声明呈现；平台不因某个字段恰好叫 includeRisk、reportId 或 collection 而附加业务含义。正常跳过可选分支不自动等于业务资料不完整；真实失败、取消及 unknown 证据始终可见。 |
| D05 | 仅更新独立分发的工作流数据，不改变 Core 可执行制品 digest，也不要求重新构建前端；历史 Run 保留原包、展示声明、资源/插件绑定及 Core 制品身份。 |
| D06 | 插件离线时，已确认输出、通用产物与执行证据仍可读取；业务页面链接及专用业务解释由公开声明或插件提供，Core 不拼接 Finance/Notes 专用路由或读取其业务表。 |

外部模型与金融 provider 的真实可用性、容量和费用不由本地受控服务测试证明。专家编辑器和服务配置的复杂能力仍须由结构化控件覆盖，不能以源码编辑作为验收替代；当前图视口不是拖拽式定义制作器，也不提供模型能力探测。Playwright 自动化体验验证和代理浏览器演练不冒充真实用户研究，只证明实际演练过的场景；控件、恢复路径和插件页面仍需改后浏览器复测。

# 产品说明

SignalDeck 是供可信单用户使用的个人 Agent 工作流平台。操作者在 Workflow Package 中定义可复用 Agent 和声明式 DAG，绑定模型与工具资源，手动或定时启动运行，并检查执行图、调用证据及产物。当前使用对象、部署和数据政策以 [`STATUS.md`](../STATUS.md) 为准。

本文描述当前产品。SD-TARGET-001 的目标要求以冻结提交 `bca05dcd666e96561426224b89b0e06aed186a22` 的 [`迭代目标`](迭代目标.md) 和 STATUS 记录的用户补充决定为准；已有页面、实现或局部测试不等于目标 A01–A18 全部验收通过。

## 产品范围

核心导航包括 Dashboard、Workflow Packages、Resources、Plugins、Scheduled Tasks 和 Runs。Finance 的 Templates、Reports 和业务页面由独立 Finance 插件提供，Core 的 Plugins 页面可以打开插件公布的业务页面。

工作流定义根始终是 Workflow Package。当前包协议为 `signaldeck.workflowPackage/v2`，包中包含 `agents` 和 `workflows`。不提供认证/RBAC 产品面、多租户、插件市场、Studio、Tryout、memory、fork、portfolio、simulation 或 backtest。

## Workflow Packages

编辑器提供 YAML、Structure 和 Graph 视图。Structure 编辑包元数据及 Agent/Workflow JSON，应用草稿后更新同一 YAML；它不是另一套运行定义。Graph 显示编译后的依赖边及 `control`、`input`、`condition` 来源。校验诊断提供字段路径，并在可定位时提供 YAML 行列。

Agent 具有输入/输出 schema、工具和资源授权、执行预算以及一种策略：模型策略引用模型资源并使用 prompt；确定性策略调用一个已授权工具并映射输入和输出。Agent 不拥有节点依赖，可被包内不同节点或 Workflow 复用。节点通过 `uses` 引用 Agent，声明显式依赖、输入映射、条件、接受的上游终态和最大尝试次数；不能以递归 Agent/Workflow 调用扩展执行。

控制、输入引用和条件引用共同形成 DAG。编译器拒绝环、未知引用、不安全 YAML、无法满足的输入类型和不支持的 schema 约束。schema 使用固定的闭合子集，不接受任意 JSON Schema。保存生成内容寻址的包修订，后续编辑更新当前指针，不修改已有 Run 的定义。

启动页从已保存 Workflow 的输入 schema 生成输入表单并支持 JSON 编辑。启动会校验参数、工具契约、资源所有权和授权，冻结实际采用的定义、资源配置、凭据版本引用、插件发布和 Core 制品，再创建 Run。资源不可用或契约不匹配会返回明确错误；校验定义通过不承诺外部服务可用。

## Resources 与 Plugins

Resources 统一管理 `model` 和 `tool` 资源。模型资源支持 OpenAI-compatible `chat_completions` 和 `responses`，配置 endpoint、model ID 和 timeout；工具资源配置插件所有者、非敏感 scope、并发上限和请求速率。Agent 只能使用其授权的资源。

凭据单独写入、加密保存。读取仅显示是否存在凭据和版本标识；编辑时不提交新凭据表示保留已有值。更新凭据会产生新版本，尚未完成的旧 Run 若再需要原版本，会明确失败为绑定已变化，不会静默使用新凭据。

Plugins 管理发布描述和启用状态，展示工具契约、制品身份及已有调用产生的健康观测。列出插件不会连接或初始化插件；没有观测时显示未观测，不宣称在线。新运行使用所需且启用的发布；历史运行保留其原发布身份。

当前独立制品为 Finance、Digital Oracle 和非金融 Notes。安装描述与业务进程部署是两个操作；保存描述不会自动构建或启动容器。插件可独立升级，但旧 Run 需要保留对应旧制品和 endpoint。插件编写、配置和升级契约见 [`writing-extensions.md`](writing-extensions.md)。

## Runs

Temporal 持有执行生命周期，浏览器关闭不会停止已接受的运行。就绪节点按各自依赖启动，受 Workflow 并发上限约束；无关慢分支不会形成全局步骤屏障。Agent 工具并发与外部资源限流分别控制。

Run 状态为 `queued`、`running`、`succeeded`、`failed`、`cancelled`。节点和调用证据进一步区分 `blocked`、`skipped`、`timed_out`、`unknown` 等状态。条件为假产生跳过；不接受上游终态产生阻断；缺失输出必须按定义显式处理，不生成伪造结果。Workflow 可选择继续独立分支或失败后停止。

取消请求记录接受时间并通过引擎传播，界面区分“请求取消”和实际终态。取消不能撤销已发生的外部效果。写调用响应丢失时保留原 `operationId` 和 `unknown`，先依赖插件查询或去重能力核实；无法确认时保留不确定结果，不盲目重写。重试沿用原 deadline；具有写工具授权的 Agent 不通过整节点自动重启重新选择写操作。

Run Detail 分别提供运行依赖图、调用归属树、依赖/产物关系和不可变快照。证据可追溯节点、Agent、模型或工具操作以及网络尝试；大值以内容寻址产物引用展示并可读取。跨 Run 读缓存仅在 Agent 显式声明策略时使用，界面显示来源 Run/operation、获取时间和过期时间。恢复同一 Run 复用已确认调用；新运行默认重新获取数据。

Rerun 创建新 Run，保留原包修订、输入及来源 Run，重新解析当前资源、插件和 Core 制品，使用新的运行 deadline；它不会复制旧 Run 的执行结果。当前没有包或 Run 删除入口。

## Scheduled Tasks

计划选择包和 Workflow，保存参数 JSON、cron、IANA timezone、暂停状态、错过触发的 catch-up 时间窗，以及 `skip`、`buffer_one` 或 `allow` 重叠策略。日历和时区语义由 Temporal Schedule 执行；不再使用旧 interval/daily/weekly/monthly 或 placeholder 模板协议。

计划修改先保存期望配置，记录同步修订和失败状态，并可由 dispatcher 重试投递。每次 fire 有独立触发身份和关联 Run；计划动作等待实际 Run 生命周期结束，使重叠策略覆盖完整执行时间。手动 Trigger 使用稳定请求身份，响应丢失重投不会主动创建新的逻辑触发。

页面显示同步状态、触发历史、关联运行和失败原因。删除计划停止未来调度并保留已有 fire 和 Run 来源。计划保存或触发需要引擎可用，读取既有计划与运行不需要初始化插件。

## Finance 业务

Finance 独立页面和 API 拥有 Markdown Templates、模板编译、Reports 的创建、上传、读取和下载。普通业务报告按其 API 规则编辑；Agent 创建的报告保留调用来源，禁止覆盖或删除。市场数据和其他金融工具由 Finance 发布契约定义，金额、数量和市场价值使用字符串。Digital Oracle 拥有其市场研究 provider 与来源 warnings；上游不可用时不得伪造数据。

# 产品说明

## 产品问题与用户

SignalDeck 为个人操作者提供一个可信的单用户 LLM agent 流水线运行器。操作者用 YAML 组织多个 agent、工具和 HTTP 操作，手动或按计划启动工作流，并检查实际输入、输出、失败和资源使用证据。

当前交付目的是完成本地开发调试和个人使用的闭环：配置模型连接，编辑工作流包，选择工作流与输入，启动运行，检查证据并按需重跑。部署、数据、兼容政策和开发档位以 [`STATUS.md`](../STATUS.md) 为准。

## 范围与入口

| 入口 | 当前功能 |
| --- | --- |
| Dashboard `/` | 最近 10 次运行及这 10 次运行的状态计数，进入运行详情。 |
| Workflow Packages `/workflow-packages` | 列表、创建、YAML 导入、分区编辑、校验、导出、Secret Bindings，以及独立启动页。 |
| Model Connections `/model-connections` | 全局模型连接的创建、编辑、删除、连接测试、能力探测及只读能力证据。 |
| Scheduled Tasks `/scheduled-tasks` | 为包内指定工作流创建计划，预览输入、修改配置、暂停/恢复、run-now、查看触发历史和删除。 |
| Runs `/runs` | 按状态、包、工作流或模型连接筛选，检查队列和执行证据，取消运行或从快照重跑。单次运行删除由后端 API 提供，当前浏览器没有独立删除入口。 |
| Templates `/templates` | Markdown 模板创建、编辑、占位符参考、运行输入、编译预览、生成报告和删除。 |
| Reports `/reports` | 从模板生成或上传 Markdown，搜索/筛选报告，查看、编辑内容、下载和删除。 |

Workflow Package 是唯一的可执行工作流编写入口。包内保存 inputs、agents、output schemas、capability profiles、私有 MCP 配置及 workflow graph；没有独立的全局 agent 或 workflow 编辑器。

Templates 和 Reports 由静态扩展 `signaldeck.finance` 提供，归在 Finance Workspace 导航组。`signaldeck.digital_oracle` 提供运行时工具，不增加独立页面；Tools 是后端只读元数据能力，在工作流包的能力配置中使用。

以下不属于当前范围，除非项目被明确重新划定范围：公共登录、多用户认证、RBAC、组织和租户、插件市场、live broker execution、portfolio accounting、workflow memory、run fork、Studio、Tryout、orchestration、runtime-v2、simulations 和 backtests。

## 核心用户流程

1. 按 [`README.md`](../README.md) 启动本地组合栈并打开浏览器。若后端要求 API token，浏览器在收到未授权响应后提示输入 token。
2. 创建 Model Connection，设置协议、endpoint、模型和 API key；保存后可执行连接测试和能力探测。
3. 创建或导入 Workflow Package，配置包内资源和 Workflow YAML，校验后保存包。启动页使用已保存版本；编辑器有未保存改动时，启动操作会先提示确认。
4. 在独立启动页显式选择包内 workflow，填写该工作流的输入，执行 preflight 并启动；或者创建引用该包和 workflow key 的 Scheduled Task。
5. 运行进入 queued，由 scheduler 领取后执行冻结快照；操作者在 Runs 中观察终态、逐步证据和输出。
6. 需要复现或改变根输入时，从运行详情打开 rerun draft，在 readiness 允许后创建新运行。重跑沿用原运行的包快照，不读取包的当前编辑版本。
7. 需要报告时，使用已保存模板和运行输入生成 Markdown 报告，或上传 Markdown，再查看、编辑或下载报告。

## 功能需求

### 工作流包与启动

包清单使用 `signaldeck.workflowPackage/v1` YAML，通过稳定的 Model Connection key 引用全局模型，通过 owner-qualified tool key 引用工具。一个包可以声明多个工作流；节点支持 `step`、`http`、`sequence`、`fanout` 和 `loop`。

编辑器从已保存的 manifest source 恢复包内资源；包摘要不能替代完整清单。清单无法读取或解析时，编辑和保存应进入明确的阻塞状态。导入、校验、保存和启动必须经过后端包解析与语义校验，具体 YAML、schema、引用和确定性编译约束见 [`开发规范.md`](开发规范.md)。

启动输入优先使用 schema 生成的表单，也支持高级 JSON。支持表单的 schema 必须在 preflight/launch 前将 JSON 校验并应用到同一份输入；无法转换为表单的 schema 使用 JSON 模式并显示原因。切换 workflow 时重置输入和 readiness；未选择、已删除或无法读取的工作流不能启动。点击启动会针对当前输入重新执行 preflight，阻塞项必须解决，警告单独显示。

Secret Bindings 通过独立写入表单设置，读取只显示 key、存在性和时间戳。已保存的 API key、包 secret 和私有 MCP `env`、`headers`、`query` 值不应从读取、导出或运行来源中回显；导出包也不携带数据库内部 id、运行历史或 Secret Binding 记录。

### Runs

手动 launch 和 scheduled fire 产生 queued run，并捕获不可变的包快照及已解析的非 secret 模型运行配置。运行状态包括 `queued`、`running`、`succeeded`、`failed` 和 `cancelled`；取消 queued run 立即生效，running run 在步骤边界协作停止。

详情提供 Output、Execution、Overview、Input、Runtime 和 Usage 标签页。操作者可以分别检查步骤、agent invocation 和 HTTP operation 的输入/请求、输出/响应与错误，并查看包来源、队列进度、重试/失败分类和 token 用量。URL 可定位标签页及证据对象；自动刷新仅在已加载运行仍处于 queued/running 时持续。

rerun 只允许通过 draft 编辑根参数，新运行保留来源关系。删除一个运行不删除源包或计划；删除 Workflow Package 会删除其拥有的 runs。

### Scheduled Tasks

计划固定引用一个包及包内 workflow key，支持 `interval`、`daily`、`weekly`、`monthly` recurrence 和 IANA timezone，可配置起止时间。重叠策略为 `skip` 或 `queue`；错过策略为 `skip` 或 `catchUpOne`，并有 misfire grace 配置。

每日、每周和每月计划按所选时区的本地时间计算。春季跳时中不存在的时间按时区转换顺延，例如纽约 2026 年 3 月 8 日的 02:30 会在 03:30 触发；秋季重复时间只取第一次。每月计划跳过当月不存在的日期。

输入模板可使用 `schedule`、`fire`、`window`、`lastRun`、`vars` placeholders，渲染结果按所选 workflow input schema 校验。预览展示模板上下文、渲染输入和诊断，不持久化或启动运行。run-now 创建普通运行并关联 manual fire；触发历史显示 scheduled/manual 原因、pending/queued/skipped/failed 状态、渲染参数和关联运行。

包或工作流不可用时，依赖该工作流输入的操作和 run-now 必须给出不可用原因；计划的时间、暂停状态等配置仍可独立管理。删除计划停止未来自动化并移除计划拥有的 fire，已有 run 保留自身的 schedule provenance。

### Model Connections 与 Tools

Model Connection 使用 `openai_chat_completions` 或 `openai_responses` 协议，保存 endpoint、model、超时、reasoning effort 和加密 API key。连接 key 在创建后保持稳定。API key 只写入；编辑时留空表示保留已有值。

连接测试与能力探测针对已保存的连接执行；界面展示测试结果、探测时间和文本生成、工具调用、结构化输出等能力证据，以及后端解析的运行策略。这些能力证据是只读的，不把未探测能力显示为已支持。

Tools 只读返回静态扩展声明的工具元数据，包通过本地 capability profile 授予工具。未知 native tool 不得静默回退为 MCP。

### Templates 与 Reports

Templates 使用 Markdown 和 `{{placeholders}}`，支持插入占位符、提供 runtime inputs 和即时编译预览。生成报告使用已保存模板；修改模板草稿后应先保存再生成对应版本的报告。

Reports 按唯一 slug 保存 Markdown 内容及来源元数据；来源可以是 `compiled`、`uploaded`、`external` 或 `agent`。报告内容可独立编辑，后续模板修改不会自动重编译已生成报告。

## 可观察验收

当前交付至少应能观察到以下结果：

- 按入口文档启动后，浏览器可访问服务，健康和数据库就绪检查通过。
- 预置 demo package 可被发现；配置有效模型连接后，能选择工作流、填写输入并完成 preflight 和启动。
- 一次运行从 queued 进入终态，在 Runs 中可检查包快照、步骤与 agent/HTTP 证据、错误或最终输出；冻结快照的 rerun 保留来源关系。
- Scheduled Task 能完成创建、输入预览、暂停/恢复、run-now 和历史查看；删除计划后已有关联运行仍能读取自身来源。
- 模板和报告能完成生成、查看、编辑、下载闭环，并支持 Markdown 上传。
- 无效清单、无效输入和不可用依赖给出可定位的诊断；读取、导出和错误信息不返回已保存的原始 secret。
- 受影响代码通过 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 和 [`开发规范.md`](开发规范.md) 指定的适用检查。

## 已知约束

外部模型、HTTP endpoint 和 MCP server 的可用性由相应服务决定。模型连接的测试或能力证据不能保证之后每次调用成功；失败应保留为可检查的运行结果。部署边界或使用对象改变时，按 [`STATUS.md`](../STATUS.md) 的条件重新评估范围与验收。
